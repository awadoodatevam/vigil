# Provider spikes (P-06, P-20, P-07)

Owner-run spikes against the real services (`docs/packages/P-06.md` Sections 6 and 6.11), run on the owner's Mac with `spikes/providers/run.sh {spike} [--package P-20]`. Each spike writes one result file `spikes/results/P-06-{name}.json` and the requests and answers it saw, without secrets or personal data, under `dev/fakes/recordings/` (each folder's `README.md` describes its files); P-19 and P-21 test their connectors on these recordings. The spikes of P-07, `teams` and `email` (`docs/packages/P-07.md` Section 6), write `spikes/results/P-07-SB-T-06.json` and `spikes/results/P-07-AR-SP-02.json` and their recordings under `dev/fakes/recordings/teams/` and `email/`, which P-22 uses. The gate runs only the tests (`test_*.py`), against fakes; it never calls a real service.

With `--package P-20` (`docs/packages/P-20.md` Section 6.14, P-20's owner-run step) a spike writes `spikes/results/P-20-{name}.json` instead, and its recordings go to a temporary folder that `run.sh` removes when it ends, so the recordings under `dev/fakes/recordings/` and the `P-06-*.json` result files stay as they are. P-20 runs `claude`, `openai` and `local-model` this way: `P-20-claude.json`, `P-20-openai.json` and `P-20-SB-T-04.json`. Since P-20 the requests are those of the product's SL-T-1 and SL-T-2 (member alert lines `- {alert type} | {component} | {source} | {detail} | fired {time}`, the hypothesis as `Root-cause hypothesis: …`, the SL-T-1 system text of P-20 Section 6.10, and in SL-T-2 the part `E4` with the summary of the accepted answer's evidence entry), and every SL-T-1 answer is also checked by the product's output checks (`rejection_reasons` in `request_data.py`, the reasons of P-20 Section 6.11).

## Prerequisites (P-06 spec Section 6.11 step 1)

- Prepaid credit on the Anthropic and OpenAI accounts, and their keys stored as `claude` and `openai`; the secret `jira` stored again with `expires_on` (the date the token shows at Atlassian): the commands of `deploy/edge.md` "Operator secrets".
- The Claude key MUST be created inside a workspace (Claude Console, API keys, Create key, then choose a workspace such as Default). An organisation-level key is refused with "This API key is not scoped to a workspace, so this request must include the anthropic-workspace-id header".
- The Jira token is made with "Create API token", not "Create API token with scopes" (a scoped token fails basic authentication against the site address), with the longest expiry Atlassian allows.
- The AWS Session Manager plugin (`brew install --cask session-manager-plugin`), for `similarity` and `local-model`.
- `python3.12` (BP-OT-10): Homebrew's, or python.org's after its "Install Certificates.command" was run (otherwise every HTTPS call fails with `CERTIFICATE_VERIFY_FAILED`).
- `aws login --profile vigil` and `export AWS_PROFILE=vigil`.
- For `similarity`: the main host running with `vigil-embed` (`deploy/edge.md`). For `local-model`: the GPU host started with `deploy/gpu.sh start`.

For `teams` and `email` (P-07 spec Section 6.8 step 1):

- `aws login --profile vigil` and `export AWS_PROFILE=vigil` (the secrets `teams-team-{key}`, `teams-user-{username}` and `smtp`, BP-OT-14).
- The Teams desktop client signed in as a member of "Techfinity Demo".
- Outlook on the web with full access to `vigil-noc-l1@techfinity.ae` and `vigil-dbops-engineer@techfinity.ae` for the owner's account.

## The owner's questions (`teams`, `email`)

What only a person can see is asked by the spike in the terminal, after it has sent (the email spike asks first, before it sends to a mailbox, that its Inbox is open). Each answer is a check of the result file. A question ends with its prompt: `(y or n) ` (type `y`, `yes`, `n` or `no`, then Enter; any other answer asks again), `(Enter, or n) ` (Enter alone, or `n` and Enter), `(Enter) ` (Enter) or `> ` (paste the copied link, then Enter). A yes-or-no check passes with yes and fails with "the owner answered no". A pasted link passes when it is the link sent; otherwise the detail is "no link pasted", "the link was rewritten by Safe Links" (a `safelinks.protection.outlook.com` address whose `url` parameter is the link) or "the pasted link is not the link sent". The answers themselves are not written. When standard input ends (Ctrl-D), the spike asks and sends nothing more: the open question's check and every later check are listed with "no answer", and the result file is written.

- `teams`: after the nine posts, for each channel whose post passed: `lines-{key}` (does the message show its four lines, printed below the question, each on its own line?) and `link-{key}` (right-click the link, choose Copy link, and paste it).
- `email`, per mailbox: open its Inbox and press Enter; then the ten messages are sent; `arrival-{key}`: press Enter as soon as all accepted messages are in the Inbox (passed when that is at most 60 s after the first message was accepted), or after two minutes type `n` (then: are the missing messages in Junk Email?); `lines-{key}`: does every message show four lines with the link whole, as the message printed below does?; `link-{key}`: copy the link of that message and paste it.

## What `run.sh` does

Any argument other than a spike name, optionally followed by `--package P-20` (not for `teams` and `email`), prints `Usage: spikes/providers/run.sh jira|claude|openai|similarity|local-model [--package P-20] | teams | email` and exits 2. With `--package P-20` it sets `VIGIL_SPIKE_PACKAGE=P-20` and `VIGIL_SPIKE_RECORDINGS` to a new temporary folder (`mktemp -d`), removed when the script ends. It checks the AWS identity and `python3.12`, creates the virtual environment `spikes/providers/.venv` with `spikes/providers/requirements.txt` (PyYAML) when it does not exist, and runs the spike there. `jira`, `claude` and `openai` call the services directly. `similarity` and `local-model` open a Systems Manager port forward (`AWS-StartPortForwardingSessionToRemoteHost`) from a free local port to port 11434 of `vigil-embed` (its `vigil-net` address, found by `host-address.sh` on the main host) or of `vigil-llm` (`10.40.1.20`), wait until `/api/tags` answers through it, run the spike with `--address http://127.0.0.1:{port}`, and end the forward when they end. Measured times therefore include the port forward from the Mac (well under one second).

Each spike reads its secrets with `aws ssm get-parameter` and keeps them in memory; a missing or invalid secret stops it before any file changes. It removes the `*.json` files of its recording folder, makes its calls (writing each recording as soon as the call ends), prints one line per check (`{check}: passed` or `{check}: FAILED ({detail})`) and `result: {path}`, and exits 0 when every check passed, 1 otherwise, 2 for wrong arguments. A file that would hold a secret, the Jira account's email or its account ID is not written: the spike stops with "A secret would be written to {path}; nothing written.".

`teams` and `email` take no `--package`; `run.sh` runs `teams_spike.py` or `email_spike.py` directly, with its standard input passed on. Usage lines: `Usage: spikes/providers/run.sh jira|claude|openai|similarity|local-model [--package P-20] | teams | email`, `Usage: teams_spike.py` (any argument), `Usage: email_spike.py [--address {host}:{port}]`.

The Python modules can also be run directly (Python 3.12 with PyYAML): `jira_spike.py [--address {url}]`, `ai_spike.py claude|openai [--address {url}]`, `similarity_spike.py --address {url}`, `local_model_spike.py --address {url}`, `teams_spike.py`, `email_spike.py [--address {host}:{port}]` (the SMTP server, default `email-smtp.us-east-1.amazonaws.com:587`, the host and port of `endpoint.smtp`). `VIGIL_SPIKE_RESULTS` and `VIGIL_SPIKE_RECORDINGS` change the result and recording folders (the tests use temporary folders); `VIGIL_SPIKE_PACKAGE` names the result files (`P-06` when unset).

## Result files

The `P-20-*.json` files have the format of the `P-06-*.json` file of the same spike. Every result file is a JSON object with `spike`, `run_id` (the UTC start time `YYYYMMDDTHHMMSSZ`), `started_at`, `finished_at`, `passed` and `checks` (`{name, passed, detail}` in the order run; `detail` "not run" for a check whose answer does not exist), plus:

- `P-06-SB-T-07.json`: `token_expires_on`, `token_days_left`, `issue_key`, `search` (`attempts`, `seconds_after_create`). Checks: `token-expiry`, `myself`, `create`, `search`, `read-description`, `comment`, `status-before`, `resolve`, `reopen`.
- `P-06-claude.json` and `P-06-openai.json` (and `P-20-claude.json`, `P-20-openai.json`): `calls`, per call `{call, status, duration_ms, input_units, output_units, reasoning_units, cost_usd}` (AR-G-14; `cost_usd` a string with 6 decimals), with `cites_rb_db_01` and `rejection_reasons` (since P-20: the list of reasons of the product's output checks, empty when accepted; `null` without an answer) for `sl-t-1` and `summary_length` for `sl-t-2`. Checks (Claude `stop`, OpenAI `complete`): `sl-t-1-status`, `sl-t-1-stop`/`-complete`, `sl-t-1-output`, `sl-t-1-accepted` (since P-20; "not run" without an answer), `sl-t-1-usage`, the same four without `accepted` for `sl-t-2` (sent only when `sl-t-1-output` passed, with the parts `Investigation` and `E4` only when `sl-t-1-accepted` passed), `truncated`, for OpenAI `embed-status`, `embed-vectors`, `embed-usage`, then `bad-key`.
- `P-06-SB-T-03.json`: `dimensions`, `calls` (`{call, prompt_eval_count, duration_ms}`), `scores` (the five highest rounded cosine scores, best first). Checks: `past-1`, `storm-1`, `past-2`, `storm-2`, `same-vectors`, `best-match`.
- `P-06-SB-T-04.json` (and `P-20-SB-T-04.json`): `durations_ms`, `max_duration_ms`, `prompt_eval_counts`, `eval_counts`, `load_durations_ns`, `prompt_eval_durations_ns`, `eval_durations_ns`, `ps` (the `/api/ps` entry of the model), `cites_rb_db_01`, `rejection_reasons` (since P-20; five entries each, a list of reasons per call, `null` when the call got no answer). Checks: `model-present`, `warm-up`, `chat-1`, `accepted-1` (since P-20) to `chat-5`, `accepted-5`, `gpu-fit`. `passed` is true only when every check passed; P-20's pass rule (4 of 5 accepted) is judged from the checks.
- `P-07-SB-T-06.json`: `channels`, per channel in DD-F-07 order `{key, address, status, duration_ms}` (`status` `null` when the post had no answer). Checks: `post-{key}` for the nine channels (2xx passes, AR-K-18), then per channel `lines-{key}` and `link-{key}` ("not run" when its post failed).
- `P-07-AR-SP-02.json`: `from` (the `From` header), `server` (`{host}:{port}`), `mailboxes`, per mailbox `{key, address, accepted, seconds_to_arrival, missing_in_junk, checked_message}` (`accepted` the number of messages accepted; `seconds_to_arrival` with one decimal, `null` when not asked or not answered; `missing_in_junk` true or false after an `n` at the arrival question, otherwise `null`; `checked_message` the message `j` of the `lines` and `link` questions, `null` when not chosen). Checks per mailbox: `connect-{key}`, `send-{key}-1` to `send-{key}-10`, `arrival-{key}`, `lines-{key}`, `link-{key}` (the last four "not run" when `connect` failed; the last three when no message was accepted).
