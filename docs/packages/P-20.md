### 6.1 General rules

- Every public type of `vigil-knowledge` is in `vigil.knowledge.api`, of `vigil-investigation` in `vigil.investigation.api` (AR-R-04); every other new class is package-private. The `@ApplicationModule` declarations of every module stay unchanged (`vigil-knowledge`: `shared`, `tenancy :: api`, `aigateway :: api`, `audit :: api`; `vigil-investigation`: `shared`, `incidents :: api`, `servicemap :: api`, `knowledge :: api`, `aigateway :: api`, `audit :: api`). `vigil-knowledge` uses `audit :: api` not at all in this package: the knowledge settings change only by the state machine DM-SM-15 (the Stateful part of DM-E-67), which writes no `configuration_changed` event (CTX-D-064 (12)).
- Persistence with `JdbcClient`; transactions with `TransactionTemplate`; ids from `Ids.newId()`; time from the `Clock` bean through `Timestamps.now(clock)`; every statement filtered by `tenant_id`; no `DELETE`. Requests to other modules inside a transaction join it (AR-R-10). JSON with a `static final JsonMapper` (Jackson 3); `jsonb` read back is compared as a tree.
- External calls (AR-R-09): `KnowledgeService.search`, `KnowledgeImport.importPart`, `InvestigationStepHandler.start` and `evaluate` call `TransactionGuard.assertNoTransaction()` first; the re-run worker and the re-embedding worker call the gateway only on their own threads with no transaction open. Every write that follows a gateway call happens in a transaction opened after the call returned.
- Lengths are Unicode code points; "cut to n" keeps the first n code points. "Comma-separated" means joined with `, `. Sorting of keys and texts is by code point (as `IncidentTexts.CODE_POINTS`). Times written into AI request texts are ISO 8601 in UTC to the second (Example: `2026-11-10T09:15:02Z`).
- `null` arguments of public requests: `IllegalArgumentException("a required argument is missing")`.
- Actors: requests of `vigil-investigation` to other modules use `Actor.module("vigil-investigation")`; `vigil-knowledge` makes no request that takes an actor.
- Logging (complete list at `INFO` or above from `vigil.knowledge` and `vigil.investigation`): `INFO` `re-embedding of tenant {tenant id} finished with provider {provider key}` once per DM-SM15-T2; `WARN` `re-embedding of tenant {tenant id} with provider {provider key} did not succeed ({outcome key or "unusable vectors"}); retried within 30 s` once per failed batch; `WARN` `AI re-run {request group id} of incident {incident id} for tenant {tenant id} failed ({exception class simple name})` when a re-run thread ends with an exception. No part text, answer text or vector is logged.
- AI output (CTX-D-064 (12)): a string value of a provider's answer that holds U+0000 counts as absent, and an array with such an element counts as not an array of strings (PostgreSQL stores no U+0000); `raw_output` is stored with every U+0000 replaced by U+FFFD.
- pgvector in SQL (the migrations run with a search path without `public`): the type is written `public.vector`, the distance `OPERATOR(public.<=>)` and the dimension function `public.vector_dims`.
- Every list returned is unmodifiable. Texts named in this spec are exact.

`RunbookFile.read(String text)` returns `RunbookFile.Read(List<RunbookPart> runbooks, List<String> problems)` (DD-R-09; complete rules, in this order):

1. The text is split on `\n`; a `\r` at the end of a line is removed. Every line that starts with `## ` starts a runbook whose heading is the rest of the line with leading and trailing white space removed; the runbook's lines are those after its heading line up to the next such line or the end. Lines before the first heading are not read. No heading at all: the one problem `08-runbooks.md: no runbook`.
2. The table is the run of consecutive lines starting with `|` that begins at the runbook's first line that is not blank. When there is no such line, when it does not start with `|`, or when the run has fewer than two lines: `08-runbooks.md '{heading}': no field table`, and the runbook gives no `RunbookPart`. The first two lines of the run are the header and the separator, not checked. Each further line, white space removed at both ends, MUST start and end with `|` and hold exactly two cells between them (split on `|`, each cell with white space removed at both ends): else `08-runbooks.md '{heading}': table row {n} is not '| field | value |'` (`n` from 1 for the first line after the separator), and the line is not read.
3. Fields (complete list, the names of DM-E-63): `runbook_key`, `version`, `title`, `applicable_alert_types`, `applicable_component_kinds`. Another field name: `08-runbooks.md '{heading}': unknown field {field}`; a field written twice: `08-runbooks.md '{heading}': field {field} appears more than once` (the first value counts); after the table, each field not written, in the order of the list: `08-runbooks.md '{heading}': missing field {field}`. A runbook with any of these problems gives no `RunbookPart`.
4. The two list fields: the value `(any)` is the empty list; any other value is split on `,`, each element with white space removed at both ends (an empty element is kept as the empty text). `text` is the runbook's lines after the table's last line, joined with `\n`, with white space removed at both ends (`String.strip`).

`PastIncidentFile.read(String text)` returns `PastIncidentFile.Read(List<Map<String, String>> rows, List<String> problems)` (CSV as RFC 4180; complete rules):

1. Records end at `\n` or `\r\n`; fields are separated by `,`. A field that starts with `"` is quoted: it ends at the next `"` that is not followed by another `"`, `""` inside it is one `"`, and it MAY hold `,` and line breaks. After a closing quote, anything other than `,` or the end of the record: `09-past-incidents.csv record {n}: text after a closing quote`; such a record gives no row and no further problem, and reading goes on at the next record. A quote that is not closed before the end of the text: `09-past-incidents.csv record {n}: a quoted field is not closed` (no further record is read). `{n}` counts data records from 1 (the header is record 0). An empty last line (the text ends with a line break) is not a record.
2. Record 0 MUST be exactly the 14 names `past_incident_key,title,record_label,opened_minutes_before_import,acknowledged_after_minutes,recovered_after_minutes,alert_count,alert_types,affected_service_keys,hypothesis_component_key,summary,fix_description,fix_action_key,fix_success_count`: otherwise the one problem `09-past-incidents.csv: the header must be {the 14 names joined by ","}`.
3. A data record with another number of fields: `09-past-incidents.csv record {n}: {k} fields, 14 expected`, and it gives no row. Each other data record gives one row: the 14 values by name, as text.

### 6.8 Runbooks and the similarity search (`Knowledge`; PM-M16-02, PM-M16-03, DM-R-50, DM-R-51, DM-E-65, DM-E-66, AR-P-07, DM-E72-R2)

`applicableRunbooks(tenant, alertTypes, componentKind)` (DM-R-50): without knowledge settings the empty list. Otherwise the active runbooks that share at least one alert type with `alertTypes` and whose `applicable_component_kinds` is empty or holds `componentKind` (with `componentKind` `null`, only runbooks with an empty set), ordered by the number of shared alert types (most first), then by `runbook_key`, the first `runbook_limit` of them.

`SearchTexts.of(alertTypes, serviceKeys, componentKey)` (DM-R-51): `alert types: {alert types, sorted, without duplicates, comma-separated}; services: {service keys, likewise}; component: {component key, or the empty text when it is null}`.

`search(request)`, in order:

1. `TransactionGuard.assertNoTransaction()`; the argument rules of Section 6.4. No knowledge settings: `IllegalStateException("knowledge settings of tenant {id} not found")`.
2. `embedding_state` is `reembedding` → `Unavailable(REEMBEDDING)`; nothing is called or stored (PM-M16-04, DM-SM15-T1).
3. The search text `SearchTexts.of(…)` of the request; with no transaction open, `AiGatewayService.embed(new EmbeddingRequest(tenant, embedding_provider_key, Ids.newId(), incident id, Set.of(ALERT_DATA, SERVICE_CONTEXT), List.of(text)))` (DM-E72-R2: the settings' provider only; DM-R-43: a live incident's search text is `alert_data` and `service_context`). `Unavailable(outcome)` → `Unavailable` with the reason of the same name (`UNREACHABLE`, `PROVIDER_ERROR`, `REFUSED_BY_DATA_ROUTING`); `Embedded` with a vector that is not usable (`Vectors.usable`) → `Unavailable(PROVIDER_ERROR)`. Nothing is stored in these cases.
4. In one transaction: the settings read again; when they are now `reembedding` or their `embedding_provider_key` is not the one used in step 3: `Unavailable(REEMBEDDING)` and nothing is stored. Otherwise the live incident's embedding is inserted (DM-E-65: `subject_kind` `incident`, `subject_key` the incident id as text, the provider key, the model name from `Embedded`, the search text cut to 2,000, the vector), then every active past incident that has an embedding with this provider key and the query's number of dimensions (`public.vector_dims(vector) = n`) is scored as `1 - (vector OPERATOR(public.<=>) CAST(:query AS public.vector))`, read as `BigDecimal` and rounded half-up to 2 decimal places in Java (AR-P-07). The best is the highest rounded score, ties to the first `past_incident_key` (DM-E66-R1). `match` when it is equal to or greater than `min_similarity`: `best_past_incident_key`, `score`, `success_count` = its `fix_success_count` and `fix_action_key` its copy; otherwise `no_match` with `score` the best rounded score when any past incident was scored, else `null`, and `best_past_incident_key`, `success_count`, `fix_action_key` `null`. The result is stored (DM-E-66: `incident_id`, `run_id` the request's, `search_text` cut to 2,000, `provider_key`, `min_similarity` the setting, `searched_at` now) and `Searched(result, past incident of a match or null)` is returned.

### 6.10 The requests (`Requests`; PM-M17-02, DM-R-43, AR-G-10 to AR-G-12, CTX-D-064 (2))

4. The evidence entries other than kind `ai_investigation`, the k-th labelled `E{k}` (from 1, AR-G-11), the entry's category: for `diagnostic_result`, `{content.diagnostic_name}: {summary}` when the content has a text `diagnostic_name`, else `{summary}`; every other kind `{summary}`. **System texts** (exactly; AR-G-12, CTX-D-064 (2)):

### 6.11 The AI task step, results and summaries (`AiTaskStep`, `Investigations`; DM-S-04, PM-M17-01 to PM-M17-06, DM-E-68, DM-E-69, AR-G-13)

The engine calls `start` and `evaluate` on the run's virtual thread with no transaction open; a throw is a failed call, retried after 5 s, 15 s and 45 s (AR-TM-05). `start` and `evaluate` do the same (the step never answers `Waiting`); `cancel` does nothing, every time. The answer is `Completed(output, null)`.

1. `TransactionGuard.assertNoTransaction()`. A step type other than `AI_TASK`, or parameters that are not an object whose `task` is `SL-T-1`, `SL-T-2` or `SL-T-3`: `IllegalArgumentException("ai task step parameters: task SL-T-1, SL-T-2 or SL-T-3")`.
2. The incident; none: `IllegalStateException("incident {id} not found")`.
3. **SL-T-1**: `investigate(tenant, incident, WORKFLOW_STEP, run id, Actor.module("vigil-investigation"), Ids.newId())`; `done` when the result was accepted, else `unavailable`.
4. **SL-T-2**: `summarise(tenant, incident, run id)`; always `done` (product map Section 10.1).
5. **SL-T-3**: `KnowledgeService.search(new SearchRequest(tenant, incident id, run id, the incident's alert types, the keys of its affected services, its hypothesis component key))`. `Searched` with `match`: in one transaction the `similarity_match` evidence entry (below), then `done`; `Searched` with `no_match`: `done`; `Unavailable` with any reason, `PROVIDER_ERROR` included (a search that could not be made counts as refused, CTX-D-064 (9)): `unavailable` (DM-S-04, DM-E72-R2).

**`investigate`** (one SL-T-1 attempt; the workflow step and the re-run): first, in its own transaction, `IncidentService.recordAiRequestGroup(tenant, Actor.module("vigil-investigation"), incident, group)` (so an attempt interrupted by a stop leaves the incident's `ai_last_request_group_id` at its group, AR-R-29; a refusal is thrown and nothing else happens); the SL-T-1 parts and request (Section 6.10) with the group id; `AiGatewayService.complete` with no transaction open; then one transaction:

- `Answered`: `OutputChecks.slT1` (below) gives the rejection reasons and the values; the result is stored (DM-E-68: `origin`, `run_id`, `requested_by`, `request_group_id`, `provider_key`, `model_name`, the values, `runbooks_supplied` the supplied runbooks `{runbook_key, version}` in the order given, `raw_output` the output text (the empty text when there is none) cut to 20,000 with `raw_output_truncated` (DM-C-11), `validation` `accepted` when there is no reason, `rejection_reasons`); the audit event (`AuditService.append`, `occurredAt` now, actor `requested_by`, `ai_result_accepted` or `ai_result_rejected`, subject type `AiInvestigationResult` and the result's id, the incident id, the summary below, no details; DM-E08-R3); for an accepted result the `ai_investigation` evidence entry (below, PM-M17-04); then `IncidentService.setAiStatus(…, AVAILABLE, null, group)` for an accepted and `(…, UNAVAILABLE, OUTPUT_FAILED_CHECKS, group)` for a rejected result (PM-M17-03).
- `Unavailable(reason)`: no result is stored; `setAiStatus(…, UNAVAILABLE, NO_PROVIDER_REACHABLE or NO_PROVIDER_ALLOWED, group)` (PM-M17-06; the same names).

A refusal of `addEvidence` or `setAiStatus` (by their guards in `Incidents.java`: `ai_investigation` evidence and `setAiStatus` need `open`, `resolved` or `closed`; `similarity_match` evidence needs `open` or `resolved`) rolls the transaction back and is thrown, so for the step it is a failed call. The provider kind name (DC-TX-01 "Provider kind name": `claude` "Claude", `openai` "OpenAI", `local_model` "Local model", `local_embedding` "Local embedding model") is that of `AiGatewayService.provider(tenant, provider key)`'s kind; when the read finds nothing, the provider key itself.

**`OutputChecks.slT1(String outputText, AnswerFinish finish, Map<String, UUID> labels, List<RunbookRef> supplied, boolean hasHypothesis)`** returns `OutputChecks.Checked(List<String> reasons, String likelyCause, Verdict verdict, List<UUID> evidenceEntryIds, String uncertainty, List<RunbookRef> runbookRefs)` (PM-M17-03, AR-G-11, AR-G-13, DM-E68-R3, DC-TX-11; a string value holding U+0000 counts as absent, Section 6.1). Nothing can be read — `finish` is `TRUNCATED` or `REFUSED`, the text is `null`, is not JSON, is not a JSON object, or the object has a property other than the five of the schema — gives the one reason "no likely cause" and no values. Otherwise the reasons, each at most once and in this order (complete list): "no likely cause" (`likely_cause` absent, not a string, or only white space); "does not say whether it confirms or disputes the hypothesis" (only when `hasHypothesis`: `hypothesis_verdict` is not `confirms` or `disputes`); "no uncertainty stated" (`uncertainty` as `likely_cause`); "no evidence reference" (`evidence_labels` absent, not an array of strings, or empty); else "refers to evidence that is not on the incident" (a label that is not a key of `labels`); "no runbook cited" (`runbooks_cited` as `evidence_labels`); else "cites a runbook that was not supplied" (a key not among `supplied`). Values: `likely_cause` and `uncertainty` when they are strings with other than white space, cut to 2,000; `verdict` `confirms` or `disputes` when `hasHypothesis` and the answer says so, else empty (DM-E68-R3); `evidence_entry_ids` the ids of the labels found in `labels`, in the answer's order, without repeats; `runbook_refs` the supplied runbooks whose keys the answer cites, in the answer's order, without repeats.

**Texts** (`Texts`; DC-TX-03, DC-TX-10; the incidents module cuts a summary longer than 200):

- Evidence `ai_investigation`: producer record the result's id; `source_system` `{provider kind name}, model {model_name}`; `collected_at` now; summary `AI investigation by {provider kind name}: {confirms or disputes} the hypothesis {hypothesis component name}; cites {runbook keys of runbook_refs, in cited order, comma-separated}.`, or without a verdict `AI investigation by {provider kind name}; cites {runbook keys, in cited order, comma-separated}.` (the cited order of DC-TX-03's first form for both, CTX-D-064 (12)); content `{"result_id", "origin", "provider_key", "model_name", "likely_cause", "verdict", "evidence_entry_ids", "uncertainty", "runbook_refs"}` (`verdict` `null` when empty); category `incident_record`.
- Evidence `similarity_match` (DM-A-13): producer record the search result's id; `source_system` `Incident history, {provider kind name of the result's provider}`; `collected_at` the result's `searched_at`; summary `Similar past incident {key} '{title}' ({record_label}), similarity {score with 2 decimal places}; fix succeeded {success_count} {time or times}.` (`time` when the count is 1); content `{"similarity_search_result_id", "past_incident_key", "past_incident_title", "record_label", "score", "success_count", "fix_action_key", "provider_key"}` (`score` a JSON number with 2 decimal places, `fix_action_key` `null` when empty); category `incident_history`.
- Audit summaries: `Incident investigation by {provider kind name} accepted.`; `Incident investigation by {provider kind name} rejected: {rejection reasons joined by "; "}.`

**`summarise`** (SL-T-2, PM-M17-05): the SL-T-2 request; `AiGatewayService.complete` with no transaction open. An `Answered` with `finish` `COMPLETE` whose output text is a JSON object with exactly the property `summary`, a string with other than white space, gives an AI summary: `text` that string cut to 2,000 (a summary longer than 600 characters is kept as it is; SB-T-02 measures the length in P-34, CTX-D-061 (5)), `source` `ai`, `provider_key` the answer's; a summary holding U+0000 counts as absent. Any other `Answered`, and `Unavailable`, give the template summary. The summary is stored in one transaction (DM-E-69, `run_id` the step's run). SL-T-2 writes no audit event and does not change `ai_status` (DM-E-32).

**Template summary** (`Texts.template`, DM-E69-R1, exactly): `{title}. {alert_count} alerts ({alert type display names, sorted, comma-separated}). Customer impact: {affected service names in the incident's order, comma-separated, or "none identified"}. Hypothesis: {hypothesis component name or "none"}. Evidence: {number of evidence entries} items.`; an alert type's display name is the `alertTypeName` of the first member whose alert has that type, or the type's key when no member has it; cut to 2,000.

**`summaryForMessage`** (DM-E69-R2), `@Transactional(propagation = REQUIRED)`: the latest summary; when there is none, the template summary of the incident now is stored (`run_id` `null`) and returned. No incident: `IllegalStateException("incident {id} not found")`.

**Reads**: `results` (`ORDER BY created_at, id`), `latestAccepted` (the accepted result, `ORDER BY created_at DESC, id DESC LIMIT 1`; DM-E68-R1), `latestSummary` (likewise over the summaries).
