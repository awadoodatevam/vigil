## 2. Goal

Build the module core of `vigil-connectors` (PM-M04): the code catalogue of the ten connector kinds with their connector types and settings structures (DM-E-09); connector instances and credential references (DM-E-10, DM-E-11), stored per tenant and imported as seed part 3 (DM-R-56 (3)) from the content of DD-F-07; the secret store interface `Secrets` that reads secret files at each use and compares presented tokens in constant time (AR-S-04, AR-S-05, BP-A-10); the monitoring source connector type (AR-K-00a) with its registry by kind; and its two implementations, `zabbix` and `alertmanager`, which turn a received webhook body into alert entries exactly as `50-architecture` Sections 12.3 and 12.4 say (proved on the 254 messages P-04 recorded from the lab) and run the connection tests of AR-K-01 and AR-K-02 with the JDK HTTP client, explicit timeouts, the transaction guard and the failure reasons of CTX-D-043. Nothing calls these operations yet: `vigil-intake` (P-13) and `vigil-setup` (P-11) are their first callers.

### 6.1 General rules

- Every public type of the module is in `vigil.connectors.api` (AR-R-04); every other class is package-private in `vigil.connectors`. The `@ApplicationModule(allowedDependencies = {"shared", "audit :: api"})` of `vigil.connectors` stays unchanged; this package uses only `shared` (and the JDK, Spring and Jackson).
- No class of this package has a `@Profile`: the beans are also created in the `migrate` profile and do nothing there.
- Time comes from the `Clock` bean through `Timestamps.now(clock)`; identifiers from `Ids.newId()`.
- Records are written with `JdbcClient` (as P-08's modules do). The import is `@Transactional` (propagation `REQUIRED`, AR-R-10). Reads are plain queries without their own transaction.
- Logging (AR-S-11): nothing at `INFO` or above per call. A secret that is not available or not usable is logged at `WARN` with the secret's name only (Sections 6.6 and 6.7 say which class writes the line). Never a secret value, a token, a presented value, an `Authorization` header or a request or answer body.
- A `null` argument of a public operation is an `IllegalArgumentException`, except where Section 6.4 or 6.7 says otherwise (`contentType` of `parse`; `presented` of `verify` and `verifyInstallationToken`, which then give `false`; the `handles` map of `importPart`).
- Every list and map this module returns is unmodifiable. `JsonNode` values it returns are deep copies, so a caller cannot change stored state.

### 6.5 Registry, instances and import (DM-E-09 to DM-E-11, PM-M04-02, AR-B-11)

**Registry.** `MonitoringConnectors`, a component that receives every bean implementing `MonitoringSourceConnector` (a `List`, empty allowed) and builds a map by `kind()`. At construction it throws `IllegalStateException` with "connector for {kind} is not a monitoring source kind" when a bean's kind has another connector type, and with "two connectors for {kind}" when two beans have the same kind; so the application does not start. `Optional<MonitoringSourceConnector> find(ConnectorKind)`. `ConnectorService` uses only this registry to reach a monitoring connector. A new monitoring kind is one `ConnectorKind` constant and one bean (PM-M04-02).

**Reads.** `instance` and `credentialReference` select by `tenant_id` and `id` (DM-C-10). `settings` is read from `jsonb` into a `JsonNode`. A stored `kind` that `ConnectorKind.fromKey` does not know cannot occur (the import refuses it); if it does, `instance` throws `IllegalStateException`.

**Import of part 3 (AR-B-11, DM-R-57).** `importPart` checks, collecting every problem before it refuses (complete list of rules, in this order; each problem one text as written; `{h}` is the record's handle, `{x}` the value concerned, both written `null` when `null`; lengths are counted in Unicode code points, as `varchar(n)` counts them):

1. The tenant has no credential reference and no connector instance yet: `connector records already exist`. (Whether the tenant exists and is `provisioning` is checked by P-11's import, which owns the order of parts; `vigil-connectors` does not depend on `vigil-tenancy`.)
2. Every handle is non-empty: `credential_references: a handle is empty` and `connector_instances: a handle is empty` (for `null` or the empty text; each text at most once).
3. Non-empty handles are unique across both lists: `handle {x} appears more than once`.
4. No non-empty handle is a key of the `handles` map given by earlier parts: `handle {x} is already used by an earlier part`.
5. Every credential reference's purpose is a key of `CredentialPurpose`: `credential_references: purpose of {h}: unknown purpose {x}`.
6. Every locator is `secret:` followed by a name of 1 to 64 characters from `a–z 0–9 -` (AR-S-04): `credential_references: locator of {h}: not of the form secret:{name}` (`{name}` written literally).
7. Every instance name is 1 to 100 characters: `connector_instances: name of {h}: 1 to 100 characters`.
8. Every instance kind is a key of `ConnectorKind`: `connector_instances: kind of {h}: unknown kind {x}`.
9. Every address is 1 to 500 characters: `connector_instances: address of {h}: 1 to 500 characters`.
10. For an instance of a known kind, `settings` has exactly the structure of its kind (DM-E-09, AR §12.2): not a JSON object (also `null`): `connector_instances: settings of {h}: not an object`; otherwise, for each key of `settingsSchema()` in schema order, absent: `connector_instances: settings of {h}: missing {key}`, or present with another type: `connector_instances: settings of {h}: {key} is not a string`, `… is not an integer` or `… is not a boolean` (a string is a JSON string; an integer is a JSON integral number that fits a `long`; a boolean is `true` or `false`; JSON `null` is none of them); then, for each key of the object not in the schema, in the object's order: `connector_instances: settings of {h}: unknown setting {key}`.
11. For an instance of a known kind, its `credentialRef` (empty text counts as `null`): when `instanceCredential()` is set and the reference is `null`: `connector_instances: credential_ref of {h}: required for kind {kind}`; when `instanceCredential()` is empty and the reference is not `null`: `connector_instances: credential_ref of {h}: not allowed for kind {kind}`; when set and allowed, it equals the handle of one of this part's `credentialReferences` (compared as text, whatever problems that reference has; when several have that handle, the first is used), else `connector_instances: credential_ref of {h}: unknown credential reference {x}`; and when it does, that reference's purpose, when it is a known key, equals `instanceCredential()`, else `connector_instances: credential_ref of {h}: purpose must be {purpose key}` (AR §12.2 column "Secret"; DD-K-10 "credentials match their purpose"). A reference that is "not allowed" is not checked further.

Within one rule, problems follow the order of the part, by the first appearance of the record or value concerned (credential references before instances in rules 2 to 4), and each distinct problem text appears once. A `null` part, `null` list or `null` list element is an `IllegalArgumentException`; a `null` `handles` map counts as empty. With one or more problems it throws `VigilError` `INVALID` with message `Part connectors refused.` and details `{"problems": [texts in the order above]}`, and stores nothing. Otherwise, in one transaction, it stores every credential reference, then every instance, each with a new id, `created_at` = `updated_at` = now; instances with `active = true` (DD-R-07 (3)), `updated_by` = `Actor.module("vigil-setup")` (the actor of installation operations, AR-S-07, as P-08), `settings` as given (written as the JSON text of the tree; `jsonb` does not keep key order, so settings are compared as JSON trees), `credential_ref_id` = the new id of the referenced handle or `null`. It returns a map from every handle of both lists to its new id. It reads no secret, writes no audit event (the import's one event is `vigil-setup`'s, DM-E08-R3) and publishes no event. `importStartedAt` is not read.

### 6.6 The monitoring connectors (AR-K-00a, AR-K-01, AR-K-02)

The beans are `ZabbixConnector` and `AlertmanagerConnector`. Each delegates `parse` to a package-private final class with one static method, `ZabbixPayloads.parse(byte[] body)` and `AlertmanagerPayloads.parse(byte[] body)`, which have no dependencies, so the parse tests are unit tests: they call these two methods with the body bytes (the content type is not read, see below); the content type case of `ZabbixParseTest` is checked through `ConnectorService.parse` in `ExternalCallGuardIT`.

Common rules of `parse` for both kinds (complete list):

- The body is decoded as UTF-8 with malformed and unmappable input reported (`CharsetDecoder` with `CodingErrorAction.REPORT`); a body that does not decode gives `ParseResult.Failed` "the body is not valid UTF-8". The content type is not read: both senders always send `application/json` (Sections 12.3, 12.4), and a body that is not JSON fails anyway.
- The decoded text is read with Jackson 3 (AR-T-15). A text that is not one JSON value, or whose value is not a JSON object, gives `ParseResult.Failed` "the body is not a JSON object" (whitespace before and after the object is allowed).
- A field "is a string" when its JSON value is a string; any other JSON type counts as absent. "Present" means a string that is not empty, unless a rule says otherwise.
- A key that appears twice in one JSON object counts with its last value (Jackson's default; the payload text is unchanged).
- Times are returned truncated to whole milliseconds (DM-C-01).
- `mappingFields` holds only fields whose value is a string (empty strings included); its order carries no meaning (tests compare it as a map).
- Any failure of Jackson to read the text (also a refusal by its default `StreamReadConstraints`, such as nesting deeper than its limit) gives `ParseResult.Failed` "the body is not a JSON object".
- `parse` never throws for any body (a `null` body is an `IllegalArgumentException`), never logs a body and makes no network call.

**`zabbix` (Section 12.3).** One entry, `entryIndex` 0, `payload` the whole decoded text (exactly, including any whitespace around the object). The entry is `Failed` with "no event_id" when `event_id` is not present; otherwise `Failed` with "unknown event_value" when `event_value` is not the string `"1"` or `"0"`. Otherwise `Normalised` with: `alertKey` = `event_id`; `status` `FIRING` for `"1"`, `RESOLVED` for `"0"`; `title` = `event_name` when present, else `null`; `sourceTime` = `event_date` and `event_time` for `FIRING`, `recovery_date` and `recovery_time` for `RESOLVED`, read with the pattern `uuuu.MM.dd HH:mm:ss` (strict resolution) as UTC, `null` when either is absent or unreadable; `sourceSeverity` = `severity` when present, else `null`; `identityPairs`, in this order: `component` = the `value` of the first tag element (an element of the `tags` array that is an object whose `tag` and `value` are strings; other elements are ignored everywhere) whose `tag` is `component`, when that `value` is present (AR §12.3: the first tag named `component`; a later one is not used); `host` = `host`, when present. `mappingFields` (complete list of names): `event_name`, `host`, `severity`, and `tag.{tag}` for each tag element, the first one of each tag name only. A `tags` that is not an array gives no tag pair and no tag field.

**`alertmanager` (Section 12.4).** The object MUST have `alerts` as an array, else `ParseResult.Failed` "the body has no alerts array". Entries are the elements of `alerts` in order, `entryIndex` from 0; an empty array gives `Parsed` with no entries. Each entry's `payload` is the exact text of that element in the decoded body: the text from the character offset of the element's first token to the character after its last token, located with the character offsets of a Jackson 3 streaming parser created over the decoded `String` (AR-P-01): for an object or array, from the start offset of its start token to the start offset of its end token (after `skipChildren()`) plus 1; for a scalar, from the start offset of its token to `currentLocation().getCharOffset()` after `finishToken()`. So escapes such as `\u0026` stay exactly as received, and whitespace between elements is not part of a payload. An element that is not a JSON object is `Failed` "the entry is not a JSON object"; an object whose `fingerprint` is not present is `Failed` "no fingerprint"; otherwise one whose `status` is not the string `firing` or `resolved` is `Failed` "unknown status". Otherwise `Normalised` with: `alertKey` = `fingerprint`; `status` from `status`; `title` = `annotations.summary` when present, else `labels.alertname` when present, else `null`; `sourceTime` = `startsAt` for `firing`, `endsAt` for `resolved`, read as `DateTimeFormatter.ISO_OFFSET_DATE_TIME` accepts it (0 to 9 fraction digits, any offset), `null` when absent or unreadable; `sourceSeverity` = `labels.severity` when present, else `null`; `identityPairs`, in this order: `component` = `labels.component` and `instance` = `labels.instance`, each when present; `mappingFields`: `label.{name}` for every string value of the `labels` object, then `annotation.{name}` for every string value of the `annotations` object (a `labels` or `annotations` that is not an object gives none).

**Connection tests.** `test(instance)` calls `TransactionGuard.assertNoTransaction()` first, then (complete list of steps; the first failing step gives the result):

1. Build the target address as text: `zabbix`: `{address}{api_path}` (the setting, concatenated exactly); `alertmanager`: `{address}/api/v2/status`. It MUST parse as a `java.net.URI` whose scheme is `http` or `https` (any case), that has a host and whose port is absent or 1 to 65535; else `Failed` "The address is not a valid http or https address.". A missing or non-string `api_path` or `username` setting (possible only in a row not written by the import) is an `IllegalStateException` ("connector instance {id} has no {key} setting"); an instance of another kind is an `IllegalArgumentException`.
2. Read the secret of the instance's credential reference through the module's internal secret reader (Section 6.7): no credential reference id, or no such reference in the instance's tenant: `Failed` "No credential is set."; the file missing or unreadable, or (for `zabbix`, whose secret goes into a header as is) a secret containing a character that an HTTP header value cannot hold (U+0000 to U+0008, U+000A to U+001F, U+007F, or above U+00FF; the JDK refuses these and names the whole value in its message): `Failed` "Secret {name} is not available." (the name from the locator), logged at `WARN` with the name only.
3. Send the request through the connector HTTP client (Section 6.8) and wait at most the monitoring test timeout for the complete answer (Section 6.8):
   - `zabbix` (AR-K-01): `POST` with the headers `Content-Type: application/json-rpc` and `Authorization: Bearer {secret}`, and exactly the body `{"jsonrpc":"2.0","method":"host.get","params":{"output":["hostid"],"limit":1},"id":1}` (UTF-8). `Passed` when the status is 200 and the answer is a JSON object whose `result` is an array. Otherwise `Failed` with the value of `error.data` when the answer is a JSON object whose `error` is an object whose `data` is a non-empty string not containing the secret (any status), else "HTTP {status}" (also for a 200 without a `result` array).
   - `alertmanager` (AR-K-02): `GET` with the header `Authorization: Basic {base64 of the UTF-8 bytes of "{username}:{secret}"}` (`username` the setting). `Passed` when the status is 200 (the answer is not read further); otherwise `Failed` "HTTP {status}".
   - An exception while building the request (after steps 1 and 2 only the address can cause one): `Failed` "The address is not a valid http or https address."; its message is never used. Any exception from sending the request or reading its answer (other than an `Error`): `Failed` with the reason of Section 6.8.
4. Every reason is cut to its first 500 characters, counted as Unicode code points (DM-C-01; DM-E-15 `last_test_reason` is Text(500)). No reason contains a secret value.

### 6.7 Secrets (AR-S-04, AR-S-05, BP-A-10)

`FileSecrets` implements `Secrets` and is the module's only reader of secret files; the connection tests use its package-private method `Optional<String> readNamed(String name)`. The folder is `vigil.secrets.dir`; the file of a secret is `{folder}/{name}`. Every use reads the file again (no cache), so a changed file needs no restart. A file is read as strict UTF-8 (as Section 6.6) and used exactly as read (no trimming; AR-S-04 files have no trailing newline). A missing file, an unreadable file, an empty file (AR-S-04 secrets are never empty) and a file that is not valid UTF-8 are "not available"; `readNamed` logs each such read at `WARN` with the name only (the only log line for these cases; the Zabbix connector logs only the bad header character case of Section 6.6 step 2). A name that is not 1 to 64 characters from `a–z 0–9 -` is an `IllegalArgumentException`.

Comparison: `ConstantTimeMatch.matches(String secret, String presented)` (package-private) computes the SHA-256 digests of the UTF-8 bytes of both and compares them with `MessageDigest.isEqual`, so the time does not depend on where or whether the values differ, or on their lengths; `false` when either is `null`.

### 6.8 HTTP client, timings and failure reasons (AR-T-13, AR-TM-01, BP-A-22)

- `ConnectorTimings` — package-private record `(Duration connect, Duration monitoringTest)`, provided by the bean method `connectorTimings()` of the package-private `@Configuration` class `ConnectorConfiguration`, with 5 s and 10 s (AR-TM-01). The numbers in the reasons "within 5 s" and "within 10 s" of BP-A-22 are these values; a test with shorter test timings sees its own numbers. Tests that need shorter timings pass a source class with `@Bean @Primary ConnectorTimings testConnectorTimings()` (as P-09's `LiveTimings`), with whole seconds.
- `ConnectorHttp` — a component holding one `java.net.http.HttpClient` (package-private accessor `HttpClient client()`), shared by the connectors of this package, built with (complete list): `version(HttpClient.Version.HTTP_1_1)` (no `h2c` upgrade on plain HTTP); `connectTimeout(timings.connect())`; `followRedirects(HttpClient.Redirect.NEVER)` (a redirect answers "HTTP {status}"); `proxy(HttpClient.Builder.NO_PROXY)` (every system Vigil calls is reached directly, AR-S-09, AR §17; a JVM-wide proxy setting of the machine, such as the `JAVA_TOOL_OPTIONS` proxy of a cloud session, does not change where a connector connects). These four settings are this package's implementation of AR-T-13 ("explicit"); later connectors MAY build their own client. It is closed when the context closes. Its package-private method `HttpResponse<byte[]> send(HttpRequest request) throws Exception` is the only way the connectors send. The connectors build every request with `.timeout(timings.monitoringTest())`; `send` does not change the request. It calls `sendAsync(request, BodyHandlers.ofByteArray())` and waits for the complete answer with `CompletableFuture.get(timings.monitoringTest().toMillis(), TimeUnit.MILLISECONDS)`, calling `cancel(true)` on the future (which aborts the exchange) when that wait times out, and throwing the `TimeoutException`; on an interrupt it calls `cancel(true)`, sets the thread's interrupt flag again and throws the `InterruptedException`.
- **Failure reasons** (`FailureReasons.of(Throwable, URI, ConnectorTimings, List<String> hidden)`, package-private, where `hidden` holds the call's secret and, for `alertmanager`, its `Basic` value; BP-A-22, CTX-D-043). The cause chain of the failure (unwrapped from `ExecutionException` and `CompletionException`) is checked in this order; the first rule that matches gives the reason (`{host}` is the URI's host as written; `{port}` its port, or 80 for `http` and 443 for `https` when it has none; `{c}` and `{t}` are `timings.connect()` and `timings.monitoringTest()` in whole seconds):
  1. a `java.net.http.HttpConnectTimeoutException` anywhere in the chain: "No connection to {host}:{port} within {c} s.";
  2. a `java.net.http.HttpTimeoutException` anywhere in the chain, or the wait for the complete answer timed out (`java.util.concurrent.TimeoutException`): "No answer within {t} s.";
  3. a `java.nio.channels.UnresolvedAddressException` or `java.net.UnknownHostException` anywhere in the chain: "Host {host} not found.";
  4. a `java.net.ConnectException` anywhere in the chain: "Could not connect to {host}:{port}.";
  5. anything else: "Connection failed: {m}.", where `{m}` is the message of the first throwable in the chain whose message is not empty, or the simple class name of the outermost throwable when none has one, with one final `.` removed from `{m}` before the sentence's `.` is added; when `{m}` contains a value of `hidden`, the simple class name of the outermost throwable is used instead.

  An interrupt while waiting gives rule 5's reason ("Connection failed: InterruptedException.").
