### 6.1 General rules

- React, TypeScript (strict), Vite, React Router, TanStack Query, CSS Modules (AR-T-08); no other runtime library. New packages are the latest release on the pin date, exact versions (BP-R-08), within the constraints of the packages already pinned; the report lists them.
- Screens read only through `vigil-api` (AR-W-02); every request is same-origin under `/api/v1` with `credentials: "same-origin"`; every `POST`, `PUT` and `DELETE` carries `X-Vigil-CSRF` equal to the cookie `vigil_csrf` (AR-S-03).
- TanStack Query: `retry: false`, `refetchOnWindowFocus: false`, `refetchOnReconnect: false`; the only re-reads are the polling of AR-I-05, the live notices of AR-I-04, a reconnection of the live stream and "Try again" (AR-W-02).
- Wording: every visible text is the exact text of `40-demo-cut` (DC-U, DC-S01, DC-S02, DC-TX-00, DC-TX-01) or of this spec; `{product}` is the tenant's `product_display_name` (DC-U-02).
- No `localStorage`, `sessionStorage` or cookie written by the web application.
- `web/src`, tests included, MUST NOT contain the texts that `SeparationTest` refuses (BP-R-06): fixtures use addresses such as `https://jira.example/browse/NOC-1`.

### 6.2 Build and generated types (BP-R-13, CTX-D-085 (11))

- `web/package.json`: new dependencies `react-router`, `@tanstack/react-query`; new development dependency `openapi-typescript`; script `generate` = `openapi-typescript ../app/src/main/resources/openapi/vigil-api.yaml -o src/api/generated/vigil-api.ts`. `web/src/api/generated/` is in `.gitignore`, `web/.prettierignore` and ESLint's `ignores`.
- `app/pom.xml`: an execution `npm-run-generate` (`npm run generate`) right after `npm-ci`, before lint, format check, type check, tests and build.
- The API client (`web/src/api/`) is a hand-written wrapper of `fetch` typed with the generated `paths` and `components` (no other HTTP library): it adds the CSRF header, aborts a request after 15 s and turns every failure into an `ApiFailure` `{status, code, reason}` (Section 6.4).

### 6.3 Routes and session (AR-W-01, DC-S01, DC-U-13, CTX-D-085 (1) to (3))

Routes (complete list for P-28): `/login` (DC-S01); `/no-access` (DC-S01-05); `/incidents` (DC-S02); `/` redirects to `/incidents`; every other path, the paths of AR-W-01 not built yet included, shows the not-found state: within the signed-in layout (banner, header) the DC-U-09 error state "Could not load this page. Not found." with "Try again" (which reloads the route); tab title `{product}` alone (CTX-D-085 (1)).

1. **Tenant first.** At start the application reads AR-I-10. A `404 unknown_host` makes every route show the DC-U-09 error state with its message ("Could not load this page. This address is not set up."), with no banner, no header and no sign-in form, and an empty tab title (AR-B-10, CTX-D-085 (13)). Any other failure of AR-I-10 shows the same state with its `{reason}` (Section 6.4). "Try again" reads AR-I-10 again.
2. **Desktop pages** (`/incidents`, `/no-access`, the not-found state) read AR-I-13 when they open. A `401` (`session_ended` or `not_signed_in`) of AR-I-13 or of any later request of the page, except `POST /api/v1/session` (item 4) and `DELETE /api/v1/session` (item 5), opens `/login?next={encodeURIComponent(path and query)}`, with the message "Your session ended. Sign in again." for `session_ended` and none for `not_signed_in`. A user without `view` on `/incidents` or on the not-found state is sent to `/no-access` (DC-U-05); a user with `view` who opens `/no-access` is sent to `/incidents`.
3. **`next`** is used only when, decoded, it starts with `/` and its second character is neither `/` nor `\`; any other value is ignored. A user who opens `/login` with a valid session goes to `next` or the default page (CTX-D-085 (2)).
4. **Sign in** (DC-S01-03): `POST /api/v1/session`. 200 → `next`, or the default page: `/incidents` with `view`, `/no-access` without. 401 → the answer's message ("Username or password is incorrect.") under the "Sign in" button, the password field emptied, the username kept. Any other failure → "Could not sign in. {reason}" under the button (DC-U-09 action failed). The button is disabled while the request runs.
5. **Sign out** (DC-S01-04): `DELETE /api/v1/session`; 204 or 401 → `/login` with "You are signed out."; any other failure → "Could not sign out. {reason}" under "Sign out".
6. The messages of `/login` are passed in the route's state, not in its address; `/login` copies the message into its component state when it mounts and then replaces its history entry without state (`navigate(pathname + search, { replace: true, state: null })`), so a reload of `/login` shows no message.

### 6.6 Formats (DC-U-07, AR-W-06, DC-TX-00, DC-TX-01)

Pure functions in `web/src/format/`, with the browser's time zone through `Intl` (or a zone passed by tests), using `hourCycle: "h23"` and the fixed month abbreviations Jan, Feb, Mar, Apr, May, Jun, Jul, Aug, Sep, Oct, Nov, Dec:

- `viewerTime(instant, now, zone)`: `HH:MM:SS` when the instant falls on the same calendar day as `now` in that zone, else `D Mon YYYY, HH:MM` (Example: "9 Oct 2026, 16:20").
- `duration(seconds)`: below 120 → `{s} s`; whole minutes → `{m} min`; else `{m} min {s} s`.
- `zoneNote(now, zone)`: "Times in UTC+hh:mm" or "Times in UTC-hh:mm" (ASCII `+` and `-`; Examples: "Times in UTC+05:00", "Times in UTC+00:00", "Times in UTC+05:30", "Times in UTC-03:00").

- The display names of DC-TX-01 for incident state, stage (`investigation` "Investigation", `response` "Response", `recovery` "Recovery", `null` empty), severity and source kind.
- `count(n, singular, plural)` and `isAre(n)` (DC-TX-00 "Counts").

### 6.8 Live updates and polling (AR-I-04, AR-I-05, AR-W-02, AR-TM-09)

`web/src/live/`:

- `useLiveTopics(topics)`: one `EventSource` on `/api/v1/live?topics={comma-separated}` per mounted screen. On each `change` notice, the screen's queries for that topic are invalidated at most once per 500 ms per topic (notices within the 500 ms cause one more invalidation at its end). On every `open` after the first, all the screen's queries are invalidated. The stream is down from an `error` event until the next `open`. When `readyState` is `CLOSED` after an `error` (the server answered with a status other than 200, such as 503 `starting` or 401), a new `EventSource` is opened after 1 s, and again each 1 s while it fails; a `401` is acted on by the page's own reads (Section 6.3 item 2), not by the stream.
- The line `LiveInterrupted` is shown, under the header, only on the screens of DC-U-08 (in P-28 the incident list) when the stream has been down for more than 5 s, and removed on `open`.
- `usePolling`: TanStack Query's `refetchInterval`, with `refetchIntervalInBackground: true`.
