## 2. Goal

Build `vigil-ai-gateway`, the only path from Vigil to AI providers: its five configuration and usage entities, seed import part 7, the provider choice with data routing and fallback for SL-T-1 and SL-T-2, the single named provider of SL-T-3, and one usage record with units and cost for every provider call. Build the AI provider connector type of `vigil-connectors` and its four kinds `claude`, `openai`, `local_model` and `local_embedding`, with the wire formats of AR-G-20 to AR-G-24 and the timeouts of AR-TM-01, tested on the requests and answers P-06 recorded from the real services. The package also builds the P-18 review fixes the owner placed here (CTX-D-059 (2) and (4)) and the owner's embedding timeout for batched calls (CTX-D-062, BP-A-30). Nothing calls the gateway yet: `vigil-knowledge` and `vigil-investigation` (P-20) are its first callers.

### 6.1 General rules

- Module boundaries (AR-Q-01): `vigil-ai-gateway` keeps its allowed dependencies `shared`, `connectors :: api`, `audit :: api` (`main/aigateway/package-info.java`); it uses `audit :: api` not at all in this package (the seed import's audit event is written by `vigil-setup`). HTTP code stays in `vigil-connectors` (AR-Q-03): the gateway reaches the providers only through `AiProviderConnector` beans of `connectors.api`.
- Persistence: `JdbcClient`, ids from `Ids.newId()`, times from the `Clock` bean through `Timestamps.now(clock)`, every statement filtered by `tenant_id`, as `RunnerRecords` does. No `DELETE`.
- External calls (AR-R-09): `AiGatewayService.complete`, `AiGatewayService.embed` and the four connectors' `complete` and `embed` call `TransactionGuard.assertNoTransaction()` first. Every database write of the gateway happens in a transaction opened after the provider call returned: DM-E-74 is immutable (DM-C-05), so its one insert per call comes after the call and nothing is written before it (AR-R-09 as amended by BP-A-30; CTX-D-062 (7)).
- Secrets and logging (AR-S-11, SL-B-14): no API key, request body, part text or answer text is logged or stored by the gateway or the connectors. A failed call is logged once at `WARN` by the gateway: `AI call failed: task {task}, provider {provider_key}, outcome {outcome}, reason {reason}`; a call refused by data routing at `INFO`: `AI call refused by data routing: task {task}, provider {provider_key}` (`{task}` is `AiTask.key()`, Example `SL-T-1`; `{outcome}` is `UsageOutcome.key()`, Example `unreachable`). Reasons never contain a secret (Section 6.5).
- Texts named in this spec are exact.

### 6.5 The connectors (`main/connectors/`; AR-K-07 to AR-K-10, AR-G-10, AR-G-13, AR-G-14, AR-G-20 to AR-G-24, AR-TM-01)

**HTTP.** All four use the `HttpClient` of `ConnectorHttp` (HTTP/1.1, connect timeout 5 s, no redirects followed, no proxy). `ConnectorHttp` gets a second send operation with a per-call timeout, `HttpResponse<byte[]> send(HttpRequest request, Duration timeout)`, used as the existing one is (`sendAsync(...).get(timeout)`, the future cancelled on timeout or interrupt); the existing `send(HttpRequest)` keeps the monitoring test timeout. `ConnectorTimings` gets the AI timeouts of AR-TM-01 as fields (complete list after the change: `connect` 5 s, `monitoringTest` 10 s, `chat` 90 s, `localChat` 120 s, `embedOne` 30 s, `embedBatch` 90 s), set in `ConnectorConfiguration`; the existing constructions in tests change with it. The whole-call timeout per call (complete list): Claude and OpenAI `complete` 90 s; local model `complete` 120 s; `embed` with one text 30 s, with more than one text 90 s (AR-TM-01 as amended by BP-A-30). Request headers besides those named below: `Content-Type: application/json`; no `User-Agent` is set by Vigil.

**Address.** The request address is the instance's `address` with any trailing `/` removed, followed by the path. An address that is not an `http` or `https` URI with a host → `Failed(PROVIDER_ERROR, "The address is not a valid http or https address.")`, no call.

**Key.** `claude` and `openai` read the API key of the instance's credential reference inside `vigil-connectors` (`ConnectorRecords.credential` and `FileSecrets.readNamed`, as `HttpSourceConnector` does). An instance without a credential reference, or whose credential reference record does not exist, → `Failed(PROVIDER_ERROR, "No credential is set.")`; an unavailable secret, or one holding a character an HTTP header cannot carry (as `ZabbixConnector` checks), → `Failed(PROVIDER_ERROR, "Secret {name} is not available.")` (`{name}` the secret's file name); no call in either case (as `HttpSourceConnector` does). An instance whose kind is not the connector's kind is an `IllegalArgumentException` (as `HttpSourceConnector`). `local_model` and `local_embedding` send no credential.

**Rendering of the parts (AR-G-10).** The user message is the parts in order, each as the line `### {label} ({categoryName})`, a line break, and the part's text; parts are joined by one empty line (`"\n\n"`). Example: `### Member alerts (Alert data)\n1. …\n\n### E1 (Diagnostic output)\n…`.

**Requests** (bodies are JSON objects with keys in this order; strings as given):

| Kind and operation | Method and path | Headers besides `Content-Type` | Body |
| --- | --- | --- | --- |
| `claude` `complete` (AR-G-20) | `POST /v1/messages` | `x-api-key: {key}`, `anthropic-version: {settings.anthropic_version}` | `{"model", "max_tokens": maxOutputUnits, "system": systemText, "messages": [{"role": "user", "content": rendered parts}], "output_config": {"format": {"type": "json_schema", "schema": outputSchema}}}` |
| `openai` `complete` (AR-G-21) | `POST /v1/responses` | `Authorization: Bearer {key}` | `{"model", "instructions": systemText, "input": rendered parts, "max_output_tokens": maxOutputUnits, "text": {"format": {"type": "json_schema", "name": outputSchemaName, "schema": outputSchema, "strict": true}}}` |

**Answers.** An answer whose status is outside 200 to 299 (also 3xx and rate limits) → `Failed(PROVIDER_ERROR, "HTTP {status}")`. A connection failure, connect timeout, name resolution failure, proxy failure or whole-call timeout → `Failed(UNREACHABLE, {reason})`, the reason by `FailureReasons` (the texts (4), (6), (7), (8) of the connection test failure reasons of `50-architecture` Section 12.1, BP-A-22); a whole-call timeout reads "No answer within {n} s." with `{n}` the call's timeout in whole seconds: `FailureReasons` gets an operation `of(Throwable failure, URI uri, ConnectorTimings timings, Duration callTimeout, List<String> hidden)` that uses `callTimeout` for that text, and the existing `of(…)` calls it with `timings.monitoringTest()`. A 2xx answer of `complete` is always `Answered` (AR-G-13): the output text, finish and units are read as below, each on its own: a missing or unreadable output gives `outputText` `null` (no output text); `finish` comes only from the field the table names and is `COMPLETE` when that field is missing or has another value; a unit that is missing or is not a non-negative integer that fits in a `long` is 0 (DM-E-74). A body that is not UTF-8 JSON gives `Answered(null, COMPLETE, 0, 0)`.

| Kind | Output text | `finish` | Units (input / output, AR-G-14) |
| --- | --- | --- | --- |
| `claude` | the `text` of the first `content` item of type `text` | `REFUSED` when `stop_reason` is `refusal`; `TRUNCATED` when it is `max_tokens`; otherwise `COMPLETE` | `usage.input_tokens` / `usage.output_tokens` |
| `openai` | the `text` of every `content` item of type `output_text` in the `output` items of type `message`, concatenated in order; `null` when there is none | `REFUSED` when a `content` item of an `output` message item has type `refusal`; else `TRUNCATED` when `status` is `incomplete`; otherwise `COMPLETE` | `usage.input_tokens` / `usage.output_tokens` |

`embed` (2xx): `openai` reads `data[i].embedding` ordered by `data[i].index` (the indexes MUST be exactly 0 to n−1, otherwise the answer counts as unreadable), units `usage.prompt_tokens`; `local_embedding` reads `embeddings[i]` in order, units `prompt_eval_count`; output units are 0 for both. Checked in this order: a body that cannot be read or has no list of vectors → `Failed(PROVIDER_ERROR, "The answer has 0 vectors for {m} texts.")`; then a number of vectors `{n}` different from the number of texts `{m}` → `Failed(PROVIDER_ERROR, "The answer has {n} vectors for {m} texts.")`; then a vector that is not an array of numbers → `Failed(PROVIDER_ERROR, "The answer has a vector that is not a list of numbers.")`. Units as for `complete` (0 when not a non-negative integer).

A reason has at most 500 characters and never contains the API key (`FailureReasons.of` with the key in its hidden values).

### 6.6 `complete` for SL-T-1 and SL-T-2 (PM-M18-01 to PM-M18-04, DM-R-45, DM-R-69, AR-G-13, AR-G-14)

1. Read, in one read-only transaction that ends before step 2: the task assignment of the task, and the provider configurations, the allowed provider kinds of the task and the data routing rules of the tenant. A tenant without a task assignment for the task → `Unavailable(NO_PROVIDER_REACHABLE)` with no record.
2. For each provider key of the assignment, in order, at position `p` (1 for the first): skip it, with no usage record, when its provider configuration does not exist, is not `active`, or its kind is not allowed for the task (none of these arises from seed import, which refuses them, Section 6.8). Otherwise, when it is not in the `allowed_provider_keys` of every category of the request's parts (DM-R-45), store a usage record with outcome `refused_by_data_routing`, units 0, cost 0, `started_at` = `finished_at` = now, and go on. Otherwise read its connector instance (`ConnectorService.instance`; an instance that does not exist or is not active is `PROVIDER_ERROR` "The connector instance is not available." with a usage record whose units are 0 and whose `started_at` and `finished_at` are both now), call the connector's `complete` with the configuration's `model_name`, the system text, the parts as `AiPromptPart(label, dataCategory.displayName(), text)`, the schema name, the schema and `maxOutputUnits`, and store a usage record: outcome `succeeded` for `Answered`, `unreachable` or `provider_error` for `Failed`; units from the answer (0 for `Failed`); cost by AR-G-14; `started_at` before the call, `finished_at` after it.
3. On `Answered`: return `Answered` with the provider key, location, model, `p`, output text, finish and units. No further provider is tried, also when the answer is refused, truncated or has no output text (DM-R-69, PM-D-14).
4. On `Failed`: go on with the next key. When no key is left: return `Unavailable(NO_PROVIDER_ALLOWED)` when the order held at least one key that was not skipped and data routing refused every such key ("data routing allowed no provider in the order", DM-E-32), otherwise `Unavailable(NO_PROVIDER_REACHABLE)` (also when every key was skipped).

Every usage record of one `complete` carries the request's `task`, `request_group_id`, `incident_id`, the set of the parts' categories (`data_categories`, sorted), the provider key, the configuration's `location` as `provider_location`, its `model_name` and the position `p` as `fallback_position`. Each record is inserted in its own transaction right after its call (or its refusal).

**Cost** (AR-G-14): `(input_units × price_input_per_million + output_units × price_output_per_million) ÷ 1,000,000`, computed with `BigDecimal` and rounded half-up to 6 decimal places. When the cost does not fit `numeric(12,6)` (reported units beyond any real answer), the record stores both units and the cost as 0; the call's result is unchanged.

### 6.7 `embed` for SL-T-3 (DM-E72-R2, DM-R-45, AR-G-14, AR-G-30)

3. Otherwise read the connector instance as in Section 6.6 (not available → a `provider_error` record and `Unavailable(PROVIDER_ERROR)`), call the connector's `embed` with the configuration's `model_name` and the texts, store one usage record (task `SL-T-3`, `fallback_position` 1, `data_categories` the request's set, outcome and units as in Section 6.6, output units 0) and return `Embedded` with the provider key, model, vectors and input units, or `Unavailable(UNREACHABLE)` or `Unavailable(PROVIDER_ERROR)`.

### 6.9 P-18 review fixes (CTX-D-059 (2) and (4), decided by owner on 26 Oct 2026)

The behaviours of CTX-D-059 (2) (a) to (e) and (4), complete list:

1. **Stop during a call** ((a)): `Runner` gets a closed flag set by `@PreDestroy` (as `RunExecutors.close` does). When `Runner.run`'s call returns while the flag is set, `run` does not end the run (it stays `running`, so restart step (1) ends it, DM-SM10-T6) and throws `IllegalStateException("the application is closing")`; `DiagnosticStep` therefore calls the runner no more and stores no result for that definition; the engine counts the thrown call as a failed attempt with its retry (`RunSteps`, AR-TM-05), so after the restart the step is called again and the definition runs again. A stop during the step's fourth attempt ends the run `failed` as any fourth failed attempt does (CTX-D-062 (10)); `vigil-engine` is not changed. `LinuxServerConnector` keeps a stopped flag set by its `stop()`; after it is set, `client()` starts no new `SshClient` but throws `IllegalStateException("the application is closing")`, which `connectAndRun` turns into `NotStarted("the application is closing")`; and `run` returns `NotStarted("the application is closing")` from a check made right after its argument and kind checks, before it reads the secret or resolves the host.
2. **Non-finite decimals** ((b)): in `Parameters`, a `decimal` parameter value, and a definition's `min` or `max`, that is a JSON number which is not finite (Example: `1e400`) is `not a number`, as a non-number is; no exception escapes.
3. **Wait rounding** ((c)): `LinuxServerConnector` rounds every remaining wait up to whole milliseconds (at least 1 ms) through a package-private `static long waitMillis(long remainingNanos)` used by every wait, so a timeout that ends during connection or key exchange gives `no result within {timeout} s` (CTX-D-058 (4)).
4. **Unexpected exceptions** ((d)): when the call of `Runner.run` (filling the command or the connector's `run`) throws a `RuntimeException` and the closed flag is not set, `run` ends the run `failed` with the exception's message, or its simple class name (`getClass().getSimpleName()`) when the message is `null` or empty (cut to the field's length as other errors are), instead of leaving it `running`, and returns the ended run as it does for a `NotStarted` result. When the closed flag is set, a call that returns or throws leaves the run `running` and `run` throws `IllegalStateException("the application is closing")` (with the thrown exception as its cause).
5. **Tests** ((e)): see Section 7 (the rows marked "P-18 review").
6. **Logging** ((4)): `app/src/main/resources/application.properties` gets `logging.level.org.apache.sshd=WARN`.
