### 6.1 General rules

- Every public type of `vigil-runner` is in `vigil.runner.api`, of `vigil-diagnostics` in `vigil.diagnostics.api` (AR-R-04); every other class is package-private in `vigil.runner` or `vigil.diagnostics`. The `@ApplicationModule` declarations of every module stay unchanged. The public types name only types of `vigil.shared` and, where Section 6.4 says so, of `vigil.connectors.api` (`TargetConnector`) or Jackson's `JsonNode` (the part records, as `ConnectorsPart` does).
- Package-private classes (complete list; the `*Test`s of Section 7 use the four marked †): `vigil.runner`: `Runner` (implements `RunnerService` and `RunnerRestart`), `RunnerRecords` (the three tables), `RunnerImporter` (implements `RunnerImport`), `Parameters` †, `Commands` †, `OutputParsers` †, `LinuxServerConnector` (the `TargetConnector` bean of `LINUX_SERVER`), `TargetConnectors` (the registry); `vigil.diagnostics`: `Diagnostics` (implements `DiagnosticsService`), `DiagnosticRecords`, `DiagnosticsImporter` (implements `DiagnosticsImport`), `DiagnosticStep` (the `DiagnosticsStepHandler` bean), `Summaries` †; `vigil.setup`: `RunnerAdapter`, `DiagnosticsAdapter`, `ServiceMapTargetCheck`, `DiagnosticOperationCheck`, `WorkflowDiagnosticCheck`.
- Static methods of the four classes marked † (exact signatures; Sections 6.6 and 6.9 define them): `Parameters`: `static List<String> definitionProblems(String prefix, JsonNode parameters)` (the definition checks of Section 6.5 rule 3 for one `parameters` list, `prefix` = `operations[i].parameters`), `static List<String> valueProblems(String operationKey, JsonNode definitions, String parametersJson)`, `static Map<String, String> texts(JsonNode definitions, JsonNode values)`; `Commands`: `static String fill(String template, JsonNode definitions, Map<String, String> texts)`, `static String quote(String value)`; `OutputParsers`: `static Optional<ArrayNode> parse(String parser, String output, JsonNode parameters)`; `Summaries`: `static String fill(String template, JsonNode values)` (`JsonNode` and `ArrayNode` of Jackson 3, `tools.jackson.databind`).
- No class of this package has a `@Profile`. Nothing runs work in the background: the SSH client of `LinuxServerConnector` is started at its first run (so the `migrate` profile starts none) and stopped at `@PreDestroy`. `RestartProcedure` (which has `@Profile("!migrate")`) calls `RunnerRestart`.
- Records are written with `JdbcClient`; transactions with `TransactionTemplate`; requests to other modules inside a transaction join it (AR-R-10). No external call is made inside a transaction (AR-R-09): `RunnerService.run`, `TargetConnector.run`, `DiagnosticsStepHandler.start` and `evaluate` call `TransactionGuard.assertNoTransaction()` first.
- Time from the `Clock` bean through `Timestamps.now(clock)`; ids from `Ids.newId()`; lengths in Unicode code points; "cut to n" keeps the first n code points.
- JSON with a `static final JsonMapper` as the other modules do (Jackson 3). JSON stored as `jsonb`, so a stored JSON value read back is the same JSON tree, not the same text.
- `null` arguments of public requests: `IllegalArgumentException` with the message "a required argument is missing".
- Actors: requests of `vigil-diagnostics` to other modules use `Actor.module("vigil-diagnostics")`; `vigil-runner` makes no request that takes an actor.
- Logging (complete list): `vigil-runner` `INFO` `operation run {run id} for tenant {tenant id}: {operation key} on {target key} ended {state key}` once per run that ends in `RunnerService.run` (including `refused`); `WARN` `operation run {run id} for tenant {tenant id} interrupted by restart` per run of Section 6.7, which gets no `INFO` line. Nothing else at `INFO` or above from `vigil.runner` and `vigil.diagnostics`. No secret, private key or command text is logged.
- Every list returned is unmodifiable.

### 6.4 Public types

**`vigil.connectors.api` additions (AR-K-00b, complete list):**

- `TargetConnector` — `ConnectorKind kind()`; `TargetResult run(TenantId tenantId, ConnectorInstanceView instance, UUID credentialRefId, String command, Duration timeout)` (Javadoc: "external call: not inside a transaction"). Implemented by `vigil-runner` (PM-M04-02); `vigil-connectors` has no implementation and does not call it.
- `TargetResult` — a sealed interface with the nested records (as `ConnectionTestResult` nests its results) `TargetResult.NotStarted(String reason)` (nothing was sent to the target: the command certainly did not run), `TargetResult.Finished(int exitStatus, String output, boolean outputTruncated, String errorOutput)` and `TargetResult.Interrupted(String reason, String output, boolean outputTruncated)` (the command was sent and no exit status was received).

### 6.5 Seed part 4 (DM-E-12, DM-E-13, DM-R-57, AR-B-11)

`RunnerImporter.importPart` checks the part and collects every problem; positions `{i}`, `{j}`, `{k}` are 0-based; a `Key` is a text matching the `Key` pattern; "absent" includes `null`. Checks (complete list, in this order):

1. The tenant already has an operation or a grant: `runner records already exist` (no other check).
2. For each `operations[i]` (prefix `O`), in this order: `operation_key` not a `Key`: `O.operation_key: not a key`; equal to an earlier operation's: `O.operation_key: used more than once`; `name` absent, empty or longer than 100: `O.name: 1 to 100 characters`; `permission_kind` not `diagnostic` or `action`: `O.permission_kind: one of diagnostic, action`; `command_template` absent, empty or longer than 2000: `O.command_template: 1 to 2000 characters`; `parameters` absent or not a JSON array: `O.parameters: not a list`, otherwise the definition checks below; `output_parser` not one of the five: `O.output_parser: one of df_row, du_top, count_bytes, single_number, removed_files`; `timeout` (written `timeout_s`, DD-R-07 (2)) absent, not a text of digits only, or not 1 to 3600: `O.timeout_s: 1 to 3600 seconds`.
3. **Definition checks** of `O.parameters[j]` (prefix `D`), in this order: not a JSON object: `D: not a mapping` (no further check of it); each written field not one of `name`, `value_type`, `required`, `min`, `max`, `allowed_values`, `max_length`, `allowed_prefixes`, in the order written: `D: unknown field {field}`; `name` not a `Key` text: `D.name: not a key`; equal to an earlier definition's name of this operation: `D.name: used more than once`; `value_type` not one of the seven: `D.value_type: one of integer, decimal, text, path, duration, enum, boolean`; `required` not a JSON boolean: `D.required: true or false`; when `value_type` is valid: each of `min`, `max`, `allowed_values`, `max_length`, `allowed_prefixes` that is present (not `null`) and that the type does not take (`min`, `max`: `integer`, `decimal`, `duration`; `allowed_values`: `enum`; `max_length`: `text`; `allowed_prefixes`: `path`), in that order: `D.{field}: not allowed for {value_type}`; then the constraints the type takes: `integer`, `duration` (whole seconds, DD-R-07 (2)) — `min` or `max` not a JSON integer: `D.{field}: not a whole number`; for `duration` one below 0: `D.{field}: at least 0`; `decimal` — `min` or `max` not a JSON number: `D.{field}: not a number`; for `integer`, `decimal` and `duration`, after those checks: when `min` and `max` are both present and valid and `min` is greater than `max`: `D.max: less than min`; `enum` — `allowed_values` absent: `D.allowed_values: missing`; not a JSON array or empty: `D.allowed_values: at least one value`; an element not a JSON string: `D.allowed_values[{k}]: not a text`; equal to an earlier element: `D.allowed_values[{k}]: used more than once`; `text` — `max_length` present and not a JSON integer of at least 1: `D.max_length: a whole number of at least 1`; `path` — `allowed_prefixes` absent: `D.allowed_prefixes: missing`; not a JSON array or empty: `D.allowed_prefixes: at least one path`; an element that is not a JSON string matching `^(/[^/]+)+$` or that has a segment `..`: `D.allowed_prefixes[{k}]: not an absolute path`.
4. For each `target_access_grants[i]` (prefix `G`), in this order: `target_key` not a `Key`: `G.target_key: not a key`; `connector_instance` absent, not a handle of `handles`, or a handle whose instance `ConnectorService.instance` does not find: `G.connector_instance: not a connector instance of part 3`; an instance whose kind is not `linux_server`: `G.connector_instance: not a linux_server instance`; `permission_kind` not `diagnostic` or `action`: `G.permission_kind: one of diagnostic, action`; `credential_ref` absent, not a handle of `handles`, or not found by `ConnectorService.credentialReference`: `G.credential_ref: not a credential reference of part 3`; when the permission kind is valid and the reference's purpose is not `target_{permission kind}`: `G.credential_ref: purpose must be target_diagnostic` (or `target_action`); when the target key and the permission kind are valid and an earlier grant has both: `G: a second grant for {target_key} {permission_kind}` (DM-E13-R2). DM-E13-R1 follows from the purpose rule: a credential reference has one purpose, so the diagnostic and the action grant of a target never share one.

`null` `operations` or `grants` lists, or a `null` element, are an `IllegalArgumentException` ("a required argument is missing"). With problems: `VigilError` `INVALID` `Part runner refused.` with details `{"problems": [...]}`, nothing stored. Otherwise, in one transaction: each operation (`timeout` the seconds of `timeout_s`; `parameters` the written array as JSON; `active` true, DD-R-07 (3)) and each grant (`connector_instance_id` and `credential_ref_id` from `handles`; `active` true), `created_at` = `updated_at` = now; no audit event (DM-E08-R3), no event.

`vigil.setup.RunnerAdapter` (a `SeedPartImporter` for part 4): `SeedShapes shapes = new SeedShapes()`; `shapes.list(file, "operations", List.of("operation_key", "name", "permission_kind", "command_template", "parameters", "output_parser", "timeout_s"), Set.of("parameters"))` and `shapes.list(file, "target_access_grants", List.of("target_key", "connector_instance", "permission_kind", "credential_ref"), Set.of())` of `04-operations-actions-recovery.yaml` (as `ConnectorsAdapter` does), `shapes.refuseIfAny(SeedParts.part(4).name())`, then `RunnerImport.importPart` with the rows (`timeout_s` as `timeout`, `parameters` as its tree, `null` when absent); counts `{"operations": n, "target_access_grants": m}`, no handles, no `afterCommit`.

### 6.6 Running an operation (`RunnerService.run`; PM-M05-01 to PM-M05-03, DM-E12-R1, DM-E13-R2, DM-E14-R1, DM-SM-10, AR-K-11 to AR-K-13)

**Steps (complete list, in order):**

1. `TransactionGuard.assertNoTransaction()`. Argument checks, `IllegalArgumentException`: a `null` argument or field ("a required argument is missing"); a requester that is not a module actor ("the requester must be a module"); `requestId` empty, longer than 150 or holding U+0000 ("requestId: 1 to 150 characters without U+0000"); `operationKey` or `targetKey` not a `Key` ("operationKey: not a key", "targetKey: not a key"); a `vigil-diagnostics` requester with `ACTION` ("vigil-diagnostics runs diagnostic operations only"); `parametersJson` that is a JSON object with a name holding U+0000 ("parameters: a name holds U+0000"). These store nothing.
2. In one transaction (now read once): when the tenant has a run with this `request_id`, it is returned as it is and nothing else happens (DM-E14-R1). When the operation exists and its permission kind is not the request's: `IllegalArgumentException("operation {key} is not a diagnostic operation")` (or `… not an action operation`, the request's kind), the transaction rolls back and nothing is stored (CTX-D-058 (3): DM-SM10-T1's list of refusals stays complete). Otherwise the checks below, in this order; the first that fails stores the run `refused` (DM-SM10-T1) with its `error`, `started_at` = `finished_at` = now, and returns it: (a) no operation with the key, or it is not active: `operation {key} is not an active operation`; (b) the parameter problems below, joined by `; `; (c) no active grant of the target with the operation's permission kind: `target {target_key} has no active diagnostic grant` (or `action grant`) (PM-M05-02). Otherwise the run is stored `running` (DM-SM10-T2, `started_at` now) and committed before any external call (AR-R-09). The stored `permission_kind` is the operation's (the request's when no operation exists); `parameters` the request's JSON object, or `{}` when it is not a JSON object or a string in it holds U+0000 (PostgreSQL stores no U+0000 in `jsonb`); `requested_by` the requester's module name. Every insert of a run, `refused` or `running`, is `ON CONFLICT (tenant_id, request_id) DO NOTHING`; the stored run with this request id is then read and returned, and when it is not the one just inserted nothing else happens.
3. With no transaction open: the command (below) and `TargetConnector.run(tenant, instance, grant's credential reference, command, Duration.ofSeconds(timeout))` of the connector registered for the instance's kind (`TargetConnectors`; the instance read with `ConnectorService.instance` in step 2). An instance that is missing, not active, or of a kind without a registered target connector counts as `NotStarted("connector instance of {target_key} is not an active target instance")`.
4. In one transaction, the run ends (only when it is still `running`), with `finished_at` now and the `INFO` line: `NotStarted(reason)` → `failed` for both kinds, `error` the reason (CTX-D-058 (2), which DM-E-12 `timeout` is read with: DM-SM10-T4 and T5 read "lost its connection" as lost after the command was sent; a failure before that ran nothing); `Finished` with exit status 0 → the operation's parser reads the kept output: readable → `succeeded` (DM-SM10-T3) with `output_values`; not readable, and always when `outputTruncated` is true → `failed` for both kinds (DD-F-04 `single_number`, applied to every parser, CTX-D-058 (2)), `error` `the output could not be read by {parser}`; `Finished` with another exit status → `failed` (DM-SM10-T4), `error` the error output with its trailing line breaks removed, or `exit status {n}` when that is empty; `Interrupted(reason)` (the command was sent, then the timeout or a lost connection) → `failed` for a diagnostic operation (DM-SM10-T4), `unknown` for an action operation (DM-SM10-T5), `error` the reason. `exit_status`, `output_text` and `output_truncated` are stored as the connector gave them (for `Interrupted` the output received). `error` is cut to 1,000. The ended run is returned.

**Parameter check** of the request's `parametersJson` against the operation's definitions (complete list of problems, in this order; also `RunnerService.parameterProblems`): the text is not a JSON object: `parameters: not an object` (no other problem); each written name that is not a defined parameter, in the order written: `parameter {name}: not a parameter of {operation_key}`; then each definition in its order: a required parameter absent or `null`: `parameter {name}: missing`; a value present and not `null`, by `value_type`: `integer`, `duration` (a whole number of seconds, DD-R-07 (2)) — not a JSON integer: `parameter {name}: not a whole number`; `decimal` — not a JSON number: `parameter {name}: not a number`; for these three, outside the bounds: `parameter {name}: {min} to {max}`, or `at least {min}` / `at most {max}` when one bound is absent; for `duration` a missing `min` counts as 0, so a value below 0 is always outside the bounds (Example: `max` 60 and no `min` → `parameter wait: 0 to 60`; neither → `parameter wait: at least 0`) (numbers written as plain decimals without separators); `text`, `path`, `enum` — not a JSON string: `parameter {name}: not a text`; a string holding U+0000: `parameter {name}: holds the character U+0000`; `text` longer than `max_length`: `parameter {name}: at most {max_length} characters`; `path` that does not start with `/`, holds `..`, or neither equals an allowed prefix nor starts with one followed by `/` (DM-V-06): `parameter {name}: not under {allowed_prefixes joined by ", "}`; `enum` not an allowed value: `parameter {name}: one of {allowed_values joined by ", "}`; `boolean` not a JSON boolean: `parameter {name}: true or false`.

**The command (AR-K-12, DD-R-10)** — `Commands.fill(template, definitions, texts)`: one left-to-right scan of the template; at each `{`, when the text up to the next `}` is the name of a defined parameter, `{name}` is replaced by the quoted text of its value and the scan goes on after the `}`; otherwise the `{` is kept and the scan goes on at the next character (so the braces of the awk programs stay). The text of a value (`Parameters.texts`): a string as it is; an integer its decimal digits; a decimal its plain decimal form; a boolean `true` or `false`; an optional parameter without a value the empty text. `Commands.quote(value)`: `'` + the value with each `'` written as `'\''` + `'`.

**The `linux_server` connector (`LinuxServerConnector`, AR-K-03, AR-K-11 to AR-K-13).** `run`: `TransactionGuard.assertNoTransaction()`; an instance of another kind is an `IllegalArgumentException`. The operation's `timeout` bounds the whole call from the start of the connection attempt (AR-TM-01 "whole call"): name resolution, connection, key exchange, authentication and the command all count within it; when it ends before the command was sent the result is `NotStarted("no result within {timeout} s")`, after that `Interrupted("no result within {timeout} s")` (CTX-D-058 (4)). Then, each failure giving `NotStarted` with the reason shown: (1) settings `port` a JSON integer 1 to 65535 and `host_key_sha256` a JSON string, else `connector instance {name} has no valid port or host_key_sha256`; (2) `Secrets.read(tenant, credential reference)` at each run (AR-S-04): its exception's message (Example: `Secret lab-db-01-action is not available.`); (3) the secret a JSON object with the texts `username` and `private_key`, else `the credential for {address}:{port} is not a username and private key`; the key an OpenSSH private key without passphrase, else `the private key for {address}:{port} could not be read`; (4) one SSH connection to `address`:`port` (AR-K-11), with no SSH configuration file, no known-hosts file, no agent and no identity other than the grant's key; the connection, including name resolution and the key exchange, within 5 s (AR-K-11, AR-TM-01) and within the remaining timeout; the server's host key is accepted only when its fingerprint — `SHA256:` followed by the unpadded standard base64 of the SHA-256 of the key's SSH encoding, the form `ssh-keygen -l -E sha256` prints — equals `host_key_sha256` exactly, else `host key {received fingerprint} of {address}:{port} does not match host_key_sha256`: the connection is refused before authentication and the run ends `failed` (CTX-D-058 (4)); any other failure to connect: `could not connect to {address}:{port}`; (5) public-key authentication as `username` within the remaining timeout, else `authentication as {username} on {address}:{port} failed`. (6) The command is sent on one exec channel (the users' login shell is bash, AR-K-12); from opening that channel on, the command may have started. The run waits until the channel closes, at most until the operation's timeout (counted from the start of the connection attempt) ends; then the channel and the session are closed at once: `Interrupted("no result within {timeout} s")`; a channel or session that closes without an exit status (the connection lost): `Interrupted("the command ended without an exit status")`; otherwise `Finished`. Standard output is decoded as UTF-8, malformed input and every U+0000 replaced by U+FFFD (PostgreSQL stores no U+0000; CTX-D-058 (5) extends DM-C-11's storage rule to command output); the first 65,536 code points are kept and `outputTruncated` is true when more arrived (DM-C-11); standard error likewise, its first 1,000 code points. The session is closed after every run (one connection per run, AR-K-11). `TargetConnectors` collects the `TargetConnector` beans by `kind()` at construction; two beans of one kind, or a kind whose type is not `TARGET`, are an `IllegalStateException`.

**Output parsers (AR-K-13, DD-F-04 `output_parsers`; `OutputParsers.parse(String parser, String output, JsonNode parameters)` returns `Optional<ArrayNode>`, empty when the output is not readable).** The values are a JSON array of `{"name": …, "value": …}` objects in the parser's order (the order DC-S03-08 shows; `jsonb` keeps the order of an array); "whole number" means digits only, within a signed 64-bit integer; GiB values are texts: bytes / 1,073,741,824 rounded half-up to one decimal place, always written with one decimal (Example: `"16.0"`); other numbers are JSON integers; paths are texts. Lines are split on `\n`; empty lines are ignored.

| --- | --- | --- |
| `df_row` | the last line split on runs of spaces into `<mount> <size> <used> <avail> <pcent>%`: `mount` (text), `size_bytes`, `used_bytes`, `avail_bytes`, `used_pct` (the number before `%`), `size_gib`, `used_gib`, `avail_gib` | no line; the last line does not have exactly five fields; size, used or avail not a whole number; pcent not a whole number followed by `%` |

### 6.9 The Diagnostic step (`DiagnosticStep`; DM-S-03, PM-M13-02, PM-M13-03, DM-R-64, AR-R-21)

The engine calls `start` and `evaluate` on the run's virtual thread with no transaction open; a throw is a failed call, which the engine retries after 5 s, 15 s and 45 s with a new `evaluation_count` (P-17 report Section 11 item 2). `start` and `evaluate` do the same (the step never stores `Waiting`, so the engine calls only `start`):

1. `TransactionGuard.assertNoTransaction()`. A step type other than `DIAGNOSTIC` is an `IllegalArgumentException`; parameters that are not an object whose `diagnostics` is a list of one or more key texts and whose `target` is `hypothesis_component` are an `IllegalArgumentException` ("diagnostic step parameters: diagnostics and target hypothesis_component") — content of seed part 16 cannot have them.
2. The incident (`IncidentService.incident`); none: `IllegalStateException("incident {id} not found")`. No hypothesis component: answer `Completed(failed)` with no result reference, and nothing is stored (DM-S-03; DM-E-54 needs a component).
3. The target: `ServiceMapService.target(tenant, hypothesis component)` (DM-E26-R1, current generation).
4. For each key of `diagnostics`, in list order, also after an earlier one failed (DM-S-03): when the step execution already has a result for the key, it is kept and nothing runs (DM-R-64; this is the evaluation after a restart or a retry). Otherwise: (a) no active definition: a `failed` result (with the target when there is one, no operation run), `error` `diagnostic {key} is not an active diagnostic definition`; (b) no target: a `failed` result with no target and no operation run, `error` `component {component_key} has no target`; (c) otherwise `RunnerService.run(tenant, Actor.module("vigil-diagnostics"), new RunRequest("{step execution id}:{diagnostic_key}:{evaluation_count}", DIAGNOSTIC, definition's operation, target, definition's parameter values))` (DM-E14-R1; `{evaluation_count}` is `StepCall.evaluationCount()`): a run still `running` is an `IllegalStateException("operation run {id} is still running")`; `succeeded` gives a `succeeded` result with the run's output values; any other state a `failed` result with the run's `error` cut to 500. `collected_at` is the run's `finished_at` (the refusal's time for `refused`), now for (a) and (b). Each result is stored in its own transaction as soon as its run has ended, together with, for a `succeeded` result, its evidence entry: `IncidentService.addEvidence(tenant, Actor.module("vigil-diagnostics"), incident, DIAGNOSTIC_RESULT, result id, "{target_key} via runner, operation {operation_key}", collected_at, Summaries.fill(summary_template, values), content, DIAGNOSTIC_OUTPUT)` (DC-TX-03, DM-R-44; the `source_system` form is DC-TX-03's, DM-E-38's example is illustrative, CTX-D-058 (7)), where `content` is `{"diagnostic_key", "diagnostic_name", "component_key", "target_key", "operation_key", "operation_run_id", "values"}` (`values` the array of Section 6.6). The result is inserted with `ON CONFLICT (tenant_id, step_execution_id, diagnostic_key) DO NOTHING`; when nothing was inserted (the step execution already has a result for the key), neither the result nor an evidence entry is written in that transaction (CTX-D-058 (7)). When `addEvidence` refuses (the incident became `merged` or `closed`), the transaction rolls back and the call throws, so it is a failed call. The run is then cancelled by the engine's incident listener on `IncidentStateChanged` to `merged` or `closed` (DM-R-16, end reason `incident_merged` or `incident_closed`), and part (3) of the engine discards the answer of any call still in progress (P-17 Section 6.6); the engine's re-evaluation itself checks only the tenant.
5. Answer `Completed(done)` when the step execution has a `succeeded` result for every key of `diagnostics`, otherwise `Completed(failed)`, with no result reference in both cases. The answer carries no reason (`Completed` has none): the reason of a `failed` step is the stored `error` of its `failed` diagnostic results (PM-M13-03); when there is no hypothesis component (step 2) no result is stored and P-18 records no reason. Nothing else records a reason.

**After a restart (DM-S-03, DM-E14-R1).** A run interrupted by a stop was moved to `failed` "interrupted by restart" by restart step (1) and has no result; the engine calls the step again (reason `resume`, case (g) of AR-R-20) with a new `evaluation_count`, so each definition without a stored result runs with a new request ID, and the definitions with a stored result are not run again.

`Summaries.fill(template, values)`: one left-to-right scan; a placeholder is `{` + the name of a value of the array + `}` (the name MAY hold `/` and `.`, never `}`, DD-R-10), replaced by the value's text (a JSON string as it is, a number as its JSON text); every other brace is kept. `cancel` does nothing (the step leaves nothing open, AR-R-21), every time it is called.
