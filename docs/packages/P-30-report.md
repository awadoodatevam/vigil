## 3. Deviations from the spec

None changes a text, value or behaviour the spec states. Readings of points the spec leaves open:

1. **`KEYS` of `test_storm.py`**: "The result file records `acts`" adds a key to the result file, so the existing test of the result file's exact keys (`test_immediate_run_passes`) expects `acts` after `deliveries`. Spec 6.10 item 1's list of changed tests does not name this one; it is the only way to keep both statements.
2. **The countdown** rounds the remaining time up to whole seconds (as P-29's `countdown`), so it reads "in 0 min 1 s" until `expires_at` and is not shown from `expires_at` on.
3. **A 401 of an action** opens `/login?next={path}` with "Your session ended. Sign in again." for `session_ended`, done by the page (`useAction`), since `useSessionEnd` (moved unchanged) watches only the reads.
4. **The dialog** is rendered inside the action area, so the 16 px spacing between the page's parts does not move the modal from its centre.
5. **Layout details**: "Approve" and "Reject" are direct children of the action area, 12 px apart; the expiry time and the countdown are two lines; the record label tag follows the past incident's text on the same line without a space (as P-29's evidence lines); the line of a second approval is an info notice at 14 px (VD-C-11), "Rejected by …" an info notice at 16 px like the success notice of VD-C-26.
6. **The identity wrapper** of spec 6.9 item 3 uses `Mockito.mock(IdentityService.class, withSettings().mockMaker(MockMakers.PROXY).defaultAnswer(AdditionalAnswers.delegatesTo(bean)))`: the proxy mock maker needs no agent on Java 25. Mockito comes with `spring-boot-starter-test` (Section 6).
7. **`InterruptedLine`** of `SignedInLayout` is exported and reused by `MobileLayout` with the page's single query key (`lastUpdate(client, [key])`), so both layouts show the same line.
