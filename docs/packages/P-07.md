## 2. Goal

Prove with the real services, before `vigil-notifications` and its connectors are built (P-22), that: a Teams message in the Adaptive Card payload of AR-K-18, posted through each of the nine channels' Workflows webhooks at least 300 ms apart (AR-K-19), arrives in its channel with its lines on separate lines, and its link can be copied from the Teams desktop client (SB-T-06; SL-ASM-02, AR-ASM-01, AR-ASM-02); and email sent over SMTP with STARTTLS to Amazon SES in the form of AR-K-20 reaches two of Techfinity's shared mailboxes, 10 messages each, in the inbox and not in Junk, within 60 s, with every line and the link intact (AR-SP-02; AR-ASM-04). What only a person can see is asked of the owner by the spike (CTX-D-065 (7)). Every spike keeps the requests and answers it saw, without secrets, under `dev/fakes/recordings/`, so P-22 tests its connectors on them. The package also writes the nine mailbox addresses into `deploy/values/demo.yaml` (CTX-D-065 (10)).

(`{file}` the file's path from the repository root, `{name}` the key path as written here).
- A message's link (CTX-D-065 (8)) has the form of the Acknowledge page link of AR-I-101 with a new random identifier: `https://demo.{demo_domain}/m/acknowledge/{uuid.uuid4()}` (Example: `https://demo.vigil.solviclabs.com/m/acknowledge/2f0c…`). ### 6.2 Secrets (AR-S-13)

- `teams-team-{team key}` and `teams-user-{username}`: the secret name is the locator of the delivery address's `credential_ref` in `credential_references` without the prefix `secret:`. A valid value is a string without whitespace that `urllib.parse.urlsplit` splits into scheme `https` and a non-empty host, or scheme `http` with host `127.0.0.1` (the tests' fakes). Otherwise: "Secret /vigil/demo/{name} is not valid (AR-S-13).".
- `smtp`: a JSON object with the non-empty strings `username` and `password`. Otherwise the same message.
- Values no written file may hold (the `Guard` of P-06 Section 6.2): every webhook address; the value of each webhook address's `sig` query parameter when it has one, both as written in the address and as `urllib.parse.parse_qs` decodes it; the SMTP `username` and `password`; the base64 of each, and of `\0{username}\0{password}` (`smtplib` logs in with `AUTH PLAIN` when the server offers it, as SES does, and with `AUTH LOGIN` otherwise).
- A webhook address is never written (AR-K-17; CTX-D-065 (11)): a Teams recording's `url` is `secret:{secret name}` (Example: `secret:teams-team-noc-l1`).

### 6.5 Email (AR-SP-02; `spikes/providers/email_spike.py [--address {host}:{port}]`; AR-K-20, AR-K-21)

Inputs: the SMTP server = `--address` when given (parsed by the spike itself: `{host}:{port}` split at the last `:`, a non-empty host, the port of digits only with a value from 1 to 65535), otherwise `email-smtp.us-east-1.amazonaws.com` port 587 (the host and port of `endpoint.smtp`'s demo value `smtp://email-smtp.us-east-1.amazonaws.com:587`, AR-B-07 as amended by BP-A-01); the secret `smtp`; `From` = `email.utils.formataddr(({product display name}, {from_address}))` with the product display name `tenant_settings.product_display_name` of `01-tenant-identity.yaml` ("Techfinity", DC-U-02) and `from_address` the `settings.from_address` of connector instance `email-demo` with `${demo_domain}` replaced by `demo_domain` of the values file, so "Techfinity <techfinity-demo@vigil.solviclabs.com>". The two mailboxes (CTX-D-065 (9); complete list, in this order): `noc-l1` (a team) and `dbops-engineer` (an approver), addresses `mailbox.noc-l1` and `mailbox.dbops-engineer` of the values file.

**Message** (AR-K-20): `email.message.EmailMessage(policy=email.policy.SMTP)`; headers set in this order: `From`; `To` (the mailbox address); `Subject` (line 1); `Date` (`email.utils.formatdate(usegmt=True)`); `MIME-Version: 1.0`; then `set_content("\n".join(lines) + "\n", charset="utf-8", cte="7bit")`, which adds `Content-Type: text/plain; charset="utf-8"` and `Content-Transfer-Encoding: 7bit` (setting `MIME-Version` first keeps `set_content` from adding it at the end). The lines are ASCII and line 4 is longer than 78 characters, so `cte="7bit"` keeps every line whole (another encoding would wrap the link); on the wire the lines are joined by CRLF (the SMTP policy's line end), line 1 included (DM-E02-R2). Sent as `msg.as_bytes()`.

Per mailbox, in order (complete list):

1. The owner's question (Enter): `Open the Inbox of {M} in Outlook on the web (your account, Open another mailbox) and keep it open. Press Enter when it is open.`
2. Check `connect-{key}`: `smtplib.SMTP(host, port, timeout=15)` (AR-TM-01's 15 s as the bound of P-06's reading), `ehlo()`, `starttls(context=ssl.create_default_context())`, `ehlo()`, `login(username, password)`; passed when all succeed; otherwise the detail is `{step} {code} {message}` for an `SMTPResponseException` (`step` `connect`, `ehlo`, `starttls` or `login`; `message` decoded as UTF-8 with `errors="replace"`) or the exception's text for any other error, through `Guard.redact`; the mailbox's other checks are "not run", and the spike goes on with the next mailbox.
3. Checks `send-{key}-{k}` for `k` 1 to 10, one message after the other on that connection, each built just before it is sent: `mail(from_address)`, `rcpt(M)`, `data(msg.as_bytes())`. Passed when `data`'s final reply (after the body) is 250 (AR-K-20 `sent`). A refusal fails it: a code other than 250 from `mail`, a code other than 250 or 251 from `rcpt`, a final reply of `data` other than 250 (SES's "554 Message rejected" comes back this way, without an exception), or an `SMTPResponseException` from any of the three (`data` raises `SMTPDataError` when the `DATA` command itself is not answered 354), with the detail `{command} {code} {message}` (`command` `mail`, `rcpt` or `data`; `message` decoded as UTF-8 with `errors="replace"`); after a refusal, `rset()` (its errors ignored) so the next message starts a new transaction. Any other exception fails it with its text; when it is an `SMTPServerDisconnected` or `OSError`, every later send to that mailbox fails with "connection lost". `first_accepted` is `common.monotonic()` when the first `data` answers 250. Then `quit()` (its errors ignored).
4. Check `arrival-{key}` (not run when no send passed; `{n}` the number of passed sends): the question (Enter or no) `Press Enter as soon as all {n} messages "AR-SP-02 spike {R} - message … of 10" are in the Inbox. If after two minutes some are not in the Inbox, type n and Enter.` The seconds `s` from `first_accepted` to the answer are measured for either answer (`common.half_up(s, 1)`). Enter passes when they are at most 60 (every message was accepted by SES at or after `first_accepted`, so each was in the Inbox within 60 s of its acceptance; AR-SP-02); otherwise the detail is `{s} s after the first message was accepted` (one decimal). `n` fails it with "the owner reported messages not in the Inbox", and the next question (yes or no) `Are the missing messages in Junk Email?` gives the result key `missing_in_junk` (true or false; `null` when not asked or not answered). An end of input at that question leaves `arrival-{key}` failed with its detail; the checks after it are "no answer" (Section 6.6).
5. Check `lines-{key}` (not run as 4): the question (yes or no) `Open each message. Does every one show four lines, each on its own line, with the link whole, as message {j} does here?`, with the four lines of message `{j}`, where `j` is chosen with `random.choice` among the `k` whose send passed.
6. Check `link-{key}` (not run as 4): the question (text) `Right-click the link in message {j} of 10, choose Copy link, and paste it here:`, judged by the link rule of Section 6.6 against message `j`'s link.

Result file `P-07-AR-SP-02.json`, own keys: `from`; `server` (`{host}:{port}`); `mailboxes`: per mailbox in order `{key, address, accepted, seconds_to_arrival, missing_in_junk, checked_message}` (`accepted` the number of passed sends; `seconds_to_arrival` the seconds of step 4 with one decimal, `null` when the question was not asked or not answered; `checked_message` `j`, `null` when not chosen). Recordings: `dev/fakes/recordings/email/`, one per message whose `mail` was made, `{n:04d}-send-{key}-{k}.json`, with the keys of P-06 Section 6.2 and these values: `call` `send-{key}-{k}`; `started_at` and `duration_ms` from just before `mail` to the last answer; `request.method` `SMTP`; `request.url` `${endpoint.smtp}`; `request.headers` every header of `msg` in order (`From`, `To`, `Subject`, `Date`, `MIME-Version`, `Content-Type`, `Content-Transfer-Encoding`) with its value as `msg` holds it; `request.body` the text after the first empty line of `msg.as_bytes()`, decoded as UTF-8; `response` `{status: the code of the last reply received, headers: {}, body: its text, decoded}`, or `null` when no reply was received; `error` the exception's text (through `Guard.redact`) whenever an exception ended the transaction, `null` otherwise. Each file is written with `common.write_checked`. The connection steps of step 2 are not recorded.

### 6.6 The owner's questions (`common.ask`)

`ask(question, lines=(), *, kind)` prints the question, then each of `lines` on its own line indented by two spaces, then the prompt, and reads one line from standard input with `input()`. Kinds (complete list): `yes_no` (prompt `(y or n) `; takes `y`, `yes`, `n`, `no` without regard to case or surrounding spaces and returns true or false; any other answer prints the prompt again); `enter_or_no` (prompt `(Enter, or n) `; returns true for an empty answer and false for `n` or `no`; anything else prints the prompt again); `enter` (prompt `(Enter) `; any answer returns); `text` (prompt `> `; returns the answer `strip()`ped). An end of input (`EOFError`) raises `NoAnswer`.

When a spike gets `NoAnswer`, it asks nothing more and sends nothing more: the check of the question (if it has one), and every check of the run not yet made (later questions, and in the email spike the later mailboxes' `connect`, `send`, `arrival`, `lines` and `link`), are listed with `passed` false and detail "no answer", except checks that would be "not run" for another reason (a channel whose post failed, a mailbox whose `connect` failed), which stay "not run"; the result file is written. A yes-or-no question's check passes with yes and fails with "the owner answered no".

**Link rule** (`link-*`): passed when the pasted text equals the message's link; otherwise the detail is "no link pasted" (empty), "the link was rewritten by Safe Links" (the pasted text is an `https` address whose host ends with `safelinks.protection.outlook.com` and whose `url` query parameter, decoded, equals the link: Microsoft Defender rewrites links, an owner decision item, Section 6.8), or "the pasted link is not the link sent". The answers themselves are not written (only the checks and the result keys named above), so a mistaken paste never reaches a file.

## 7. Tests (complete list)
