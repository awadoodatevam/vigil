## 2. Goal

Build the dashboard screen DC-S10 at `/dashboard` (SL-A4-10) and its navigation item (DC-U-04, BP-R-22): the page heading "Dashboard" with "Refresh", four tiles — time to acknowledge, time to recover, alerts suppressed, incidents merged — each with its value, its definition (DC-TX-01) and its baseline tagged "Illustrative baseline" (SL-A1-09, DC-U-10), and the data line that says which incidents the values include (DC-S10-03, SL-DR-03). The values come from `GET /api/v1/dashboard` (AR-I-80, P-43), read when the screen opens and when "Refresh" is pressed (DC-S10-04); nothing else re-reads them. The screen looks as `45-visual-design` v1.3 says (VD-C-28, VD-S-08). Playwright proves the starting state SB-V-38 on a tenant without alerts, and after a storm driver run the values the formulas of DM-R-53 give from the run's own times, in mode `script` the exact values of SB-S09.

### 6.2 Route, screen, navigation and title (AR-W-01, DC-U-04, DC-U-15, BP-R-22)

1. **Route.** `Screen` gains `"dashboard"`; `ROUTE_TABLE` adds `{ path: "/dashboard", screen: "dashboard" }` right after `/m/approve/:requestId` (before `/` and `*`), so the table is `/login`, `/no-access`, `/incidents`, `/incidents/:incidentId`, `/m/acknowledge/:incidentId`, `/m/approve/:requestId`, `/dashboard`, `/`, `*`. The screen is not lazy (`LAZY_SCREENS` is unchanged): `element` returns `<DashboardPage />`.
2. **Navigation.** `NAVIGATION` in `web/src/layout/Header.tsx` becomes `[{ label: "Incidents", path: "/incidents" }, { label: "Dashboard", path: "/dashboard" }]` (DC-U-04's order; BP-R-22: the screens built so far). The existing `NavLink` with `end` marks "Dashboard" on `/dashboard` only.
3. **Page.** `DashboardPage` is `<SignedInLayout access="view" screen="Dashboard" topics={[]} live={false}>`: a user without `view` goes to the no-access page (DC-S10-01, DC-U-05), the tab title is "Dashboard — {product}" (DC-U-15), the stream has the topic `tenant` only (AR-I-04 "every screen `tenant`"), and there is no live-interrupted line (the dashboard is not a screen of DC-U-08's list).

### 6.3 The read and the states (DC-S10-04, DC-U-08, DC-U-09, AR-W-02; CTX-D-097 (2))

1. **Query** (`web/src/dashboard/queries.ts`): `dashboardQuery(fetch = read)` is `queryOptions` with the key `["dashboard"]`, the function `apiGet("/api/v1/dashboard", { signal })`, `refetchOnMount: "always"` and `gcTime: 0` (so opening the screen always reads and never shows values of an earlier visit), and no `refetchInterval`. No topic re-reads it: `topicQueries` is unchanged and never returns a key that matches `["dashboard"]`, and a reconnection re-reads only `queriesOf(["tenant"])`.
2. **States** (from the query): while a read runs (`isFetching`: the opening read, "Refresh", "Try again"), `Loading` (VD-C-13) in a card stands in place of the tiles and the data line, and "Refresh" is disabled; when the latest read failed and no read runs, `PageError` "Could not load this page. {reason}" with "Try again" (`refetch()`) stands in place of the whole content, heading row included (as P-28's `IncidentsView` places it); otherwise the heading row, the tiles and the data line of the latest answer. A `401` opens the login as on every desktop page (`useSessionEnd`).
3. **"Refresh"** calls `refetch()`; it is enabled whenever no read runs. It changes nothing on the server (DC-U-05: it is shown to every viewer of the screen).

### 6.4 Content (DC-S10-01 to DC-S10-03; VD-S-08)

1. **Order** (complete list): the heading row (the page heading `<h1>Dashboard</h1>`, then the button "Refresh"); the tiles; the data line.
2. **Tiles** (DC-S10-02): four, in this order by `key` (complete list): `time_to_acknowledge` "Time to acknowledge", `time_to_recover` "Time to recover", `alerts_suppressed` "Alerts suppressed", `incidents_merged` "Incidents merged"; each from the answer's metric with that key (a key missing from the answer: its tile shows "no data" and no baseline line). Each tile is a `<section aria-labelledby>` holding, in this order: the name as an `<h2>`; the value (item 4); the definition of DC-TX-01 (complete list: "Mean time from detection to first acknowledgement", "Mean time from detection to first verified recovery", "Alerts received minus incidents", "Incidents made from 2 or more alerts"); the baseline line — the baseline value (item 4) followed by `<KindTag word="Illustrative baseline" />` (DC-U-10, VD-C-16) — shown only when `baseline_value` is not `null` (CTX-D-097 (4); `baseline_label` is not shown, since DM-E-80's label is always the tag's word).
3. **Data line** (DC-S10-03, DC-TX-00; `dataLine(live, past, labels)` in `texts.ts`): a `<p>` under the tiles: "Includes {k} live {incident or incidents} and {p} imported past {incident or incidents} labelled {labels}.", where `{k}` is `live_incidents` and `{p}` is `past_incidents`, each written with `grouped(n, 0)` of item 4 and followed by the singular noun for 1 and the plural otherwise (DC-TX-00 "Counts"), and `{labels}` is every element of `record_labels`, in the answer's order (AR-I-80 sorts them by code point, P-23), each in single quotes, joined by ", " (Example: `'Fictional record'`; `'A', 'B'`); with no label it is `'none'` (DC-TX-00 "An empty list is 'none'", CTX-D-097 (5)). Examples: "Includes 0 live incidents and 50 imported past incidents labelled 'Fictional record'."; "Includes 1 live incident and 1 imported past incident labelled 'Fictional record'."
4. **Numbers** (`web/src/format/numbers.ts`, CTX-D-097 (3)): `grouped(n, decimals)` is `new Intl.NumberFormat("en-US", { minimumFractionDigits: decimals, maximumFractionDigits: decimals, useGrouping: true }).format(n)`: a comma between groups of three digits (Example: "1,234", "1,234.5"). The value and the baseline value of a metric (`metricText(value, unit)` in `texts.ts`): `null` → "no data" (the value only; a `null` baseline is not shown); unit `minutes` → "{grouped(value, 1)} min" (Example: 5.7 → "5.7 min", 41 → "41.0 min", 11 → "11.0 min"; the answer's number loses a trailing zero in JavaScript, so the screen always formats one decimal); unit `count` → `grouped(value, 0)` (Example: 525 → "525", 0 → "0", 1000 → "1,000"). The counts of the data line use `grouped(n, 0)`.
