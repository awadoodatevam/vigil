### 6.5 Reading a generation

`ServiceMapRecords` reads with `tenant_id` in every statement. `ServiceMapGraphs` holds the immutable graph of a (tenant, generation): components, services, identity keys and the dependency edges including the implied `runs_on` edges (DM-E28-R2), loaded once and kept in a cache of at most 64 graphs (least recently used goes first; a generation never changes, so a cached graph is never stale). Every question first reads the tenant's current generation number (one query), then uses the cached graph of that generation.

### 6.6 Questions (PM-M07-02 to PM-M07-06, DM-R-05 to DM-R-07, DM-R-19, DM-E26-R1)

- **Edges.** "A depends on B" when the file lists `{from: A, to: B}`, or A's `runs_on_key` is B (DM-E28-R2); the same pair listed and implied is one edge.
- **`match`.** Over `pairs` in the given order (the connector's order, DM-R-04): the first pair whose (`sourceKind`, `name`, `value`) equals an identity key of the current generation gives that key's component. Names and values are compared exactly (case-sensitive). No match, an empty list, or no generation: `componentKey` `null`. `pairs` MAY be empty; `null` elements are ignored.
- **`relation(a, b)`** (DM-R-07): `a` equals `b` → `SAME_COMPONENT` with path `[a]`, whether or not `a` is in the generation; otherwise, when both are in the generation and `a` depends on `b` directly or indirectly → `DEPENDS_ON` with the path from `a` to `b` along edges; when `b` depends on `a` → `DEPENDED_ON_BY` with the path from `a` to `b` along reversed edges (each step goes from a component to one that depends on it); otherwise `NONE` with an empty path. A path lists the keys from `a` to `b`, both included; of several paths, the shortest; of equally short ones, the one whose key list is first when compared key by key in code point order (DM-E-29 `relation_path`). (Both cannot hold: the generation has no cycle.)
- **`dependents(c)`**: every component from which `c` is reachable along edges, `c` excluded, sorted.
- **`affectedServices(keys)`** (DM-R-19): the services whose `component_keys` include at least one of `keys`, ordered by `service_key`, each with `viaComponentKeys` = the given keys among its `component_keys`, sorted. Keys not in the generation contribute nothing; an empty collection gives an empty list.
- **`target(c)`** (DM-E26-R1): for a `server`, its `target_key`; otherwise the `target_key` of the component named in `runs_on_key`; empty when there is none or `c` is not in the generation.
- **`component`, `service`**: the record of the current generation, or empty.

### 6.7 The service map file (AR-B-06 with BP-A-24, DM-R-54, DM-R-55, DC-TX-11)

`ServiceMapFile.read(byte[] content)` (package-private, no database) returns the parsed file or a refusal with the problem texts, in two stages; the first stage stops at its first problem, which is the only problem; the second collects all.

**Stage 1 — reading** (each problem is `The file could not be read: {parser message}.`, AR-B-06; complete list of parser messages, checked in this order: each item is checked over the whole file before the next item, and of several nodes that break the same item, the first in document order (start line, then column) is reported):

1. More than 1,048,576 bytes: `the file is larger than 1 MiB`.
2. Not strict UTF-8 (as P-10 Section 6.6): `the file is not UTF-8`.
3. The text is parsed into events with snakeyaml-engine (`org.snakeyaml.engine.v2.api.lowlevel.Parse` with default `LoadSettings`); a syntax error: for a `MarkedYamlEngineException`, its problem text (`getProblem()`) followed by ` (line {l}, column {c})` from its problem mark (1-based); for any other `YamlEngineException`, the first line of its message.
4. An `AliasEvent`, an event with an anchor (`getAnchor()` present), or a scalar or collection start event with a tag written in the file (`getTag()` present — any tag, also a standard one such as `!!str`, BP-A-24): `anchors, aliases and custom tags are not allowed (line {n})`, the first such event's start line.
5. The text is composed into nodes (`org.snakeyaml.engine.v2.api.lowlevel.Compose`); no document, more than one document, or a root that is not a mapping: `the file must be a mapping of the sections services, components, identity_keys and dependencies (line 1)`.
6. A mapping key that is not a plain scalar (in any mapping of the file): `a key must be a single word (line {n})`; then a key that appears a second time in the same mapping: `duplicate key '{key}' (line {n})`.
7. A top-level key other than the four of DM-R-54: `unknown section '{name}' (line {n})` (AR-B-06); a missing one: `missing section '{name}'` (in the order `services`, `components`, `identity_keys`, `dependencies`).
8. A section that is not a sequence: `section '{name}' must be a list (line {n})`; then an entry that is not a mapping: `{section}: each entry must be a mapping (line {n})`.
9. The entries in document order; of the first entry that has a problem, its first problem in this order — in key order as written: a key not among the section's fields of DM-R-54: `{section}: unknown field '{field}' (line {n})`; `component_keys` that is not a sequence of scalars: `services: component_keys must be a list (line {n})`; any other field that is not a scalar: `{section}: field '{field}' must be a single value (line {n})`; then, in DM-R-54 field order, a missing required field (`service_key`, `name`, `component_keys`; `component_key`, `name`, `kind`; all four of `identity_keys`; both of `dependencies`): `{section}: missing field '{field}' (line {n})` with the entry's line.

A scalar's value is its text as written (plain, single- or double-quoted, block). A plain scalar `null`, `Null`, `NULL`, `~` or an empty plain scalar is "empty" for an optional field (DM-R-54) and the text `null` for a required one (also when it is the empty plain scalar). An element of `component_keys` is read as a required value. `{n}` is the 1-based start line of the node concerned (complete list): an anchor, alias or tag — its event; `a key must be a single word`, `unknown section`, `unknown field` — that key node; `duplicate key` — the key node of its second appearance; `section … must be a list`, `component_keys must be a list`, `field … must be a single value` — the value node; `each entry must be a mapping` — the entry node; `missing field` — the entry's mapping node.

**Stage 2 — the rules** (DM-R-55; each text exactly as DC-TX-11 writes it; complete list, in this order; within a rule, sections in DM-R-54 order, entries in file order and fields in DM-R-54 field order, except where rule 7 says otherwise; each distinct text once). `{key}` of an entry is: `services` its `service_key`; `components` its `component_key`; `identity_keys` the text `{source_kind} {name} = {value}`; `dependencies` the text `{from} → {to}`.

1. Value forms (DM-C-01, DM-E-25 to DM-E-28): every `service_key`, `component_key`, `owner_team_key`, `runs_on_key`, `target_key`, every element of `component_keys`, `from_component_key`, `to_component_key` and identity `name` is a valid `Key`; `name` of services and components has 1 to 100 characters; identity `value` 1 to 200; `kind`, `criticality` and `source_kind` from their lists (an empty optional `criticality` passes) — else `{section} '{key}': '{value}' is not a valid {field}.`
2. Unique keys: `services: key '{key}' appears more than once.`, `components: key '{key}' appears more than once.`
3. References: every `component_keys` element, identity `component_key`, `from_component_key`, `to_component_key` and `runs_on_key` names a component of the file: `{section} '{key}': component '{ref}' is not in the file.`
4. `components '{key}': runs_on must name a server.` (a `runs_on_key` naming a component of another kind); `components '{key}': a server cannot run on another component.` (a `server` with a `runs_on_key`).
5. `components '{key}': target_key is allowed only on a server.`
6. DM-E27-R1: a (`source_kind`, `name`, `value`) that appears more than once: `identity_keys: {source_kind} {name} = '{value}' names more than one component.`
7.
