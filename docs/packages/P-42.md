## 2. Goal

Make the merge gate cheaper without making it weaker (CTX-D-067). A push to a pull request whose changes since the last passed `gate` of that pull request are only data (the owner's spike results, recordings, the package report) runs a light gate of about two minutes instead of the full gate. The full gate runs as parallel jobs, so its time is that of its longest job. The lab tests run only when a change can affect what they start. Cloud sessions keep running `tools/check-all.sh` as one command.

### 6.1 `tools/gate_scope.py` (Python 3.12, standard library only)

`Usage: tools/gate_scope.py ci|lab` (any other arguments: that line, exit 2). It runs `git` (and, for `ci`, `gh`) as subprocesses from the repository root, found from the script's own location. Every `git diff` it runs has `--no-renames`, so a moved file names both its old and its new path.

**Path lists** (constants, complete lists; an entry ending with `/` matches every path under it, any other entry matches that path exactly):

- `LAB_PATHS` (CTX-D-067 (3)): `demo/`, `dev/recorder/`, `deploy/local/`, `deploy/local.sh`, `deploy/images.sh`, `deploy/values/local.yaml`, `spikes/storm-timing/`, `docs/31-demo-data/`, `tools/check-all.sh`, `tools/gate_scope.py`, `tools/start-docker.sh`, `tools/requirements-dev.txt`, `pytest.ini`, `.github/workflows/ci.yml`.
- `DATA_PATHS` (CTX-D-067 (4)): `docs/`, `spikes/results/`, `tests/acceptance/results/`, `dev/fakes/recordings/`; and `DATA_EXCLUDED`: `docs/31-demo-data/`. A path is a data path when it matches `DATA_PATHS`, does not match `DATA_EXCLUDED`, does not end in `.py` or `.sh`, and its last part is not `Dockerfile` or `compose.yaml`.

**`gate_scope.py lab`** (used by step (3) of `tools/check-all.sh`): prints `lab` or `no-lab` and exits 0. `lab` when `git rev-parse --verify --quiet origin/main` fails, or when any path of `git diff --name-only origin/main` or of `git ls-files --others --exclude-standard` matches `LAB_PATHS`; `no-lab` otherwise. When a `git` command other than the `rev-parse` fails, it prints `lab` (the safe answer) and the command's standard error on standard error.

**`gate_scope.py ci`** (used by the job `scope` of `ci.yml`): reads the environment variables `EVENT_NAME` and `GITHUB_OUTPUT` (always required), and, only when `EVENT_NAME` is `pull_request`, `BASE_SHA` (the pull request's base commit), `HEAD_SHA` (its head commit), `MERGE_SHA` (`github.sha`, the merge commit the jobs check out) and `GITHUB_REPOSITORY` (set by the runner, as `GITHUB_OUTPUT` is); `gh` reads `GH_TOKEN`. A required variable that is unset or empty: the line `Missing {name}.` and exit 2; `EVENT_NAME` is checked first. It decides, in this order (the first rule that applies):

1. `EVENT_NAME` is not `pull_request`: full, reason `not a pull request`.
2. `git diff --name-only {BASE_SHA}...{HEAD_SHA}` names at least one path and every path is a data path: light, reason `data only`. (This replaces the documents-only path: a pull request that changes `docs/31-demo-data/` now runs the full gate, because the Java tests read it, CTX-D-067 (4).)
3. The earlier commits of the pull request, newest first: `git rev-list --first-parent {BASE_SHA}..{HEAD_SHA}`, then `HEAD_SHA` itself dropped, then at most the first 20. For each, `gh api "repos/{GITHUB_REPOSITORY}/commits/{sha}/check-runs?check_name=gate&filter=latest&per_page=100"`; the commit has a passed gate when an entry of `check_runs` whose `app.slug` is `github-actions` has `conclusion` `success`. The first such commit is `G`. When none of the 20 has one: full, reason `no earlier passed gate`.
4. `git diff --name-only {G} {MERGE_SHA}`: when every path is a data path (also when there is none): light, reason `only data since {G short} passed`; otherwise full, reason `{first path that is not a data path} changed since {G short} passed` (`{G short}` the first 7 characters). The comparison is with the merge commit, so every change `main` has gained since the branch was made counts as well, also one that `G`'s run already had: after `main` gains code, data-only pushes run the full gate until the branch is rebased onto `main` (CTX-D-067 (4)). This is deliberate: it is never lighter than it should be.

Any failure of `git` or `gh`, or an answer of `gh` that is not a JSON object whose `check_runs` is a list, gives full with reason `could not read {command}` (`{command}` the command line run, for example `git rev-list --first-parent …` or `gh api repos/…/check-runs…`). The script then appends `mode=light` or `mode=full` to the file in `GITHUB_OUTPUT` and prints `gate: {mode} ({reason})`. It exits 0 in every case except wrong arguments and a missing variable.

## 8. Done-check (complete list)

1. BP-DC-01 to BP-DC-07 (`60-build-plan` Section 6.3).
2. On the pull request (CTX-D-067): (a) the run of the build push is full: `java` and `rest` ran at the same time and `gate` passed; (b) after it passed, the session pushes the report commit (a data-only push) and its run is light (`scope` printed `gate: light (only data since … passed)`) and `gate` passed. When `main` has gained code since the branch was made, that run is full by rule 4: the session then rebases the branch onto `main` (`git pull --rebase origin main`, then `git push --force-with-lease`), waits for a passed full run, and pushes the report commit again. Claude Code reads both runs with `gh api` (`repos/{owner}/{repo}/actions/runs?branch=p-42-faster-gate` and each run's `jobs`), waiting for each to finish, and records in the report each run's ID, mode, the start and end of every job and the total time; that last report commit gives a third, light run.
3. In the full run, the `rest` job's log shows the lab tests ran (this package changes `tools/check-all.sh`), and the `java` job's log shows only `vigil/demo-lab:local` built.
