### 6.1 General rules

- Every public type of `vigil-workflows` is in `vigil.workflows.api` (AR-R-04); every other class is package-private in `vigil.workflows`. The `@ApplicationModule` declarations of every module stay unchanged. No public type of `vigil.workflows.api` names a type of another module's `api` package; types of `vigil.shared` are used (`StepCall.StepType`, `Actor`, `TenantId`).
- Records are written with `JdbcClient`; transactions with `TransactionTemplate`; requests to other modules inside a transaction join it (AR-R-10).
- Time from the `Clock` bean through `Timestamps.now(clock)`; ids from `Ids.newId()`; lengths in Unicode code points.
- The actor of every request to another module: `Actor.module("vigil-workflows")`.
- JSON with a `static final JsonMapper` as the other modules do (Jackson 3).
- `null` arguments of public requests: `IllegalArgumentException` with the message "a required argument is missing".
- Logging: nothing at `INFO` or above (the engine logs each run).
- Every list returned is unmodifiable.
- `WorkflowsIncidentListener` has `@Profile("!migrate")`; no other class has a `@Profile`.
- `vigil-workflows` keeps its own table of the Condition fields' value types and allowed values (DM-R-25, DM-R-26) for the part 16 checks.

### 6.5 Seed part 16 (DM-E-45, DM-E-47, DM-R-57, DM-R-60, AR-B-11)

`importPart` parses `workflowJson` and checks it, collecting every problem. Positions `{i}`, `{j}`, `{k}`, `{m}` are 0-based; "absent" includes JSON `null`; "an integer" is a JSON integer; `{type}` is the step type key (Example: `approval`); a `Key` is a JSON string matching the `Key` pattern (any other JSON value is not a key); "text" is a JSON string; a parameter whose value is `null` counts as absent and is not checked by (a) or (c) below; fields not named in these checks are ignored and not stored (no unknown-field check); a Duration parameter is written in the file with the suffix `_s` (`expiry_s`, `max_wait_s`, `timer_s`, `duration_s`, `timeout_s`; DD-R-07 (2)), and in every text below `{name}` of a Duration parameter is that written form with `_s` (also in `missing`); `{name}` of any other parameter is its catalogue name. A connection refers to the first step with that `step_id`.

The checks (complete list, in this order):

1. The tenant already has a workflow: `workflow already exists` (no other check runs).
2. The part's text `null` or not a JSON object: `workflow: missing` (no other check runs).
3. `name` absent, not text, empty or longer than 100: `workflow.name: 1 to 100 characters`.
4. `version_1` absent or not an object: `workflow.version_1: missing` (no further check).
5. `version_1.origin` not `seed`: `workflow.version_1.origin: seed`.
6. `version_1.steps` absent, not a list or empty: `workflow.version_1.steps: at least one step` (no further check).
7. For each step `steps[i]` (prefix `S` = `workflow.version_1.steps[i]`), in this order: not an object: `S: not a mapping` (no further check of this step); `step_id` not a `Key`: `S.step_id: not a key`; equal to an earlier step's: `S.step_id: used more than once`; `type` not a step type key: `S.type: not a step type`; `label` absent, not text, empty or longer than 60: `S.label: 1 to 60 characters`; `position` not an object whose `x` and `y` are integers: `S.position: x and y must be integers`; `parameters` present and not an object: `S.parameters: not a mapping` (no parameter check of this step); when the type is valid and `parameters` is absent or an object, the parameter checks below (prefix `P` = `S.parameters`; absent `parameters` is an empty object).
8. `version_1.connections` present and not a list: `workflow.version_1.connections: not a list` (absent is an empty list); for each connection `connections[j]` (prefix `C` = `workflow.version_1.connections[j]`): not an object: `C: not a mapping` (no further check of it); `from_step_id` not the `step_id` of a step: `C.from_step_id: not a step`; `to_step_id` likewise: `C.to_step_id: not a step`; when `from_step_id` refers to a step of a valid type, `from_output` not one of its outputs (the catalogue's; for a Condition `otherwise` and the `label` of each of its branches that is a mapping with a text `label`, whatever that branch's own problems): `C.from_output: not an output of {from_step_id}`; the same `from_step_id` and `from_output` as an earlier connection: `C: a second connection from {from_step_id} {from_output}`.
9. When no problem was found so far, the number of steps of type `trigger` not 1: `workflow.version_1: exactly one trigger step`.

**Parameter checks** of one step, in this order: (a) each written name that is not a parameter of the type (a Duration parameter only with `_s`), in the order written: `P.{name}: not a parameter of {type}`; (b) each catalogue parameter that is required, or required by its `RequiredWhen` evaluated on the written values, and absent: `P.{name}: missing`; (c) each written parameter of the type, in the order written: `ENUM` not one of the allowed values: `P.{name}: one of {allowed values joined by ", "}`; `ENUM_SET` not a list: `P.{name}: not a list`, an element not allowed: `P.{name}[{k}]: one of {allowed values joined by ", "}`, an element equal to an earlier one: `P.{name}[{k}]: used more than once`; `KEY_LIST` or `KEY_SET` not a list: `P.{name}: not a list`, an element not a `Key`: `P.{name}[{k}]: not a key`, an element equal to an earlier one: `P.{name}[{k}]: used more than once`; an `ENUM_SET`, `KEY_LIST` or `KEY_SET` list shorter than `minItems`: `P.{name}: at least {minItems}`; `DURATION` not an integer: `P.{name}: not a whole number of seconds`, outside its bounds: `P.{name}: {min} to {max} seconds` (written without separators, Example: `P.expiry_s: 60 to 86400 seconds`); `CONDITION_BRANCHES` not a list: `P.branches: not a list`, shorter than `minItems`: `P.branches: at least 1`, and for each branch `branches[k]` (prefix `B` = `P.branches[k]`): not an object: `B: not a mapping` (no further check of it); `label` not a `Key`: `B.label: not a key`; `otherwise`: `B.label: otherwise is reserved`; equal to an earlier branch's: `B.label: used more than once`; `comparisons` absent, not a list or empty: `B.comparisons: at least one comparison`; for each comparison `comparisons[m]` (prefix `Q` = `B.comparisons[m]`): not an object: `Q: not a mapping` (no further check of it); `field` not a field of DM-R-25: `Q.field: not a condition field`; when it is one, `operator` not an operator of its value type (DM-R-26; `alert_sources`, `alert_types`, `informed_teams` and `affected_services` are sets, with `contains` and `not_contains`): `Q.operator: not an operator of {field}`; when the operator is one: `in` or `not_in` whose value is absent or an empty list: `Q.value: at least one value`; another operator whose value is absent or a list: `Q.value: one value`; when neither of these two applies, each value (for `in` and `not_in` each element of the list, or the single value) of the wrong form for the field: an ordered enum or enum field (`severity`: P1, P2, P3, P4; `hypothesis_criticality`, `highest_service_criticality`: critical, high, medium, low; `hypothesis_component_kind`: server, application, database, queue, check; `alert_sources`: zabbix, alertmanager) not an allowed value: `Q.value: not a value of {field}`; a key field or set-of-keys field (`owner_team`, `informed_teams`, `hypothesis_component`, `affected_services`, `alert_types`) not a `Key`: `Q.value: not a key`; an integer field (`affected_service_count`, `alert_count`, `escalation_level`, `reopen_count`) not an integer: `Q.value: not an integer`; a boolean field (`acknowledged`, `ai_investigation_available`) not `true` or `false`: `Q.value: true or false`. (For `in` and `not_in` a single value counts as a list of one.)

With problems: `VigilError` `INVALID` `Part workflows refused.` with details `{"problems": [...]}`, nothing stored. Otherwise, in one transaction: the workflow (`name`, `active_version_id` the version's id, `created_at` = `updated_at` = now) and version 1 (`number` 1, `origin` `seed`, `origin_ref` `null`, `published_by` `Actor.module("vigil-setup")`, `published_at` now, `change_list` `[]`, `content` the stored content below); returns an empty map; no audit event (DM-E08-R3), no event.

**Stored content (DM-V-05).** `{"steps": [...], "connections": [...]}` in the written order; each step `{"step_id", "type", "label", "position": {"x", "y"}, "parameters": {...}}`; each connection `{"from_step_id", "from_output", "to_step_id"}`. Parameters by their catalogue names (a Duration without `_s`, as an integer of seconds); all other values as written (lists keep their written order, also the Set-typed parameters: AR-P-01's sorting applies to `Set` fields, not to values inside the content `Json`); a comparison `{"field", "operator", "value"}` whose value, for `in` and `not_in`, is a list (a single value written becomes a list of one). ### 6.6 Starting live runs (PM-M11-07, DM-R-16, DM-R-22, AR-R-20)

`WorkflowsIncidentListener` (package-private, `@Profile("!migrate")`), two `@ApplicationModuleListener` methods, each in its own transaction; each does nothing when the tenant is not active (`TenantService.isActive`), the tenant has no workflow, or the incident (`IncidentService.incident`) is not `forming` or `open`:

- `IncidentCreated`: when the incident's `reopenCount` is above 0 (a late delivery after a reopen) or `EngineService.hasLiveRun(tenant, incident, 1)`: nothing. Otherwise `RoutingService.evaluate(tenant, actor, incident, WORKFLOWS)` (PM-I-16; applied while the incident is forming, DM-R-17), then `EngineService.startLiveRun(tenant, actor, incident, 1, the active version's id, its content, false)`. When the incident is opened between the evaluation's read and its `setAssignment`, `evaluate` throws `IllegalStateException` and the listener's transaction rolls back; the event registry resubmits the publication after 60 s (AR-R-14), and the second delivery records the evaluation as `assignment_frozen` and starts the run (CTX-D-055 (4); the alternative left open by the P-15 spec Section 11). (A tenant cannot have a workflow without routing rules: seed part 11 precedes part 16 and a failed part stops the import; `evaluate`'s `IllegalStateException` for missing rules is therefore not handled.)
