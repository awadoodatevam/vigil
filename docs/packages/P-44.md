## 2. Goal

Give `vigil-web` its visual design. `docs/45-visual-design.md` (CTX-D-087) defines it: tokens, typography, layout and components, and how the screens P-28 built apply them (VD-S-01 to VD-S-04). P-44 writes the tokens into one global stylesheet, bundles the two fonts, rewrites every CSS Module of `web/src` to that document, and makes only the markup changes VD-R-01 allows. Nothing the user reads, clicks or receives changes: every text, item, order, route, request and behaviour of P-28 stays as it is, and every P-28 test passes with its expected texts unchanged. Static tests prove the tokens, the contrast and the unchanged texts; Playwright proves the banner's own colour, the fonts, the widths and the focus ring on the local installation, and writes screenshots of every screen for the review.

## 6. Files and code

### 6.1 General rules

1. VD-R-01 governs every change: no text, item, order, attribute that a test or a user reads (`role`, `aria-*` other than `aria-hidden` on decorative elements, `data-testid`, `href`, `target`, `rel`, `type`, `name`, `autocomplete`, `disabled`), route, request or behaviour of P-28 changes. A component MAY get wrapping elements, class names and `data-` attributes for styling, and the decorative elements of VD-R-02, as Sections 6.3 to 6.8 list them, and nothing else (VD-R-01). `Loading`'s `role="status"` and the error states' `role="alert"` are P-28's and stay.
2. Style through CSS Modules (AR-T-08); prefer a descendant, `:nth-child` or attribute selector inside the module (Example: `.error > button`, `.table td:nth-child(8)`) to a new class on an element, so that the markup changes as little as it can. Every value is a token of `45-visual-design` Section 4 (VD-R-04); the literal values allowed are those VD-R-04 and Section 7 of that document state, listed in Section 6.2 item 4.
3. A P-28 test whose expected markup changes because of an allowed change MAY change how it reads the text or its expected markup, but MUST NOT change an expected text, an expected order or a checked attribute. The report lists every P-28 test changed and why (Section 7, last row). The P-28 tests known to need this (complete list, found against `5932cde`):
   - `incidents/strip.test.tsx`: its text reader gets, before its existing replacements, two steps: every `<span class="…">` whose class is one of `styles.source`, `styles.latestTime`, `styles.latestKind`, `styles.latestType`, `styles.latestTitle` (the names Vitest gives the module's classes) becomes `|` (the separator the tests already expect), and every other `<span…>` and `</span>` is removed; then every expected string stays as it is. "DC-S02-02 the warning colour …" compares the item's text with that reader and checks the `warning` class on it instead of the raw `<p class="…">Monitoring:` string.
   - `incidents/rows.test.tsx`: only "DC-S02-04 … the ticket link": it checks the link's `href`, `target`, `rel` and text instead of its whole markup (the glyph is inside the link). The cell reader `/<td>(.*?)<\/td>/` already removes inner tags, and no `td` or `th` gets an attribute (Section 6.6 item 2), so the other tests pass unchanged.
   - `incidents/states.test.tsx` "PartError in the table …": the strip text is compared with the tags removed.
   - `tags/tags.test.tsx` "DC-U-10 every word …": the expected markup includes the `data-kind` of Section 6.7.
   `header.test.tsx`, `tenant.test.tsx` and `states/states.test.tsx` need no change. `storm.spec.ts`'s `sample` reads `textContent`, which the wrapping does not change.
4. No new dependency besides the two font packages (Section 6.2) and the development dependency `@types/node` 22.20.5 (the version `tests/e2e/` pins), for the tests that read CSS files with `node:fs` (Section 7); no CSS framework, no CSS-in-JS, no icon library (the two glyphs are inline SVG written in the component).
