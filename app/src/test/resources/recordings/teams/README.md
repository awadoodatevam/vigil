# Recorded Teams posts

The posts of one run of the Teams spike SB-T-06 (`spikes/providers/run.sh teams`, package P-07): one message in the Adaptive Card payload of AR-K-18 to the Workflows webhook of each of the nine channels of the team "Techfinity Demo" (the Teams delivery addresses of `docs/31-demo-data/07-settings.yaml`, DD-F-07), at least 300 ms apart (AR-K-19). They are the payloads of the `ms_teams` connector tests of P-22.

One file per post made, `{n:04d}-post-{key}.json` (`n` from 1 in call order), `{key}` the delivery address's `subject_key`, in this order: `noc-l1`, `db-ops`, `vas-service-owners`, `it-apps`, `noc-shift-lead`, `noc-management`, `customer-care`, `dbops-engineer`, `dbops-lead`. Each file is a JSON object with exactly these keys: `seq` (n); `call` (`post-{key}`); `started_at` (UTC, RFC 3339 with milliseconds); `duration_ms`; `request` (`method` `POST`; `url`; `headers`, exactly `Content-Type` and `User-Agent`; `body`, the payload as sent); `response` (`status`; `headers`, only `Content-Type`, `{}` when the answer has none; `body`, the text as received) or `null`; `error` (`null`, or the text of a connection failure or timeout).

`url` is `secret:{secret name}`, the name of the secret that holds the channel's webhook address (`secret:teams-team-{team key}` or `secret:teams-user-{username}`, AR-S-13; Example: `secret:teams-team-noc-l1`), never the webhook address: the address is a secret (AR-K-17). No file holds a webhook address or the value of its `sig` parameter (as written in the address or decoded): the spike checks every file before it writes it (P-06 spec Section 6.2, P-07 spec Section 6.2).
