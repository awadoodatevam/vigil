# Recorded Jira Cloud calls

The calls of one run of the Jira spike SB-T-07 (`spikes/providers/run.sh jira`, package P-06) against the demo site: who-am-I, create an issue with a label, the label search of AR-K-14 (one to four searches), read its ADF description (AR-K-15), comment, status, resolve and reopen. They are the payloads of the `jira_cloud` connector tests of P-21.

One file per call, `{n:04d}-{call}.json` (`n` from 1 in call order), `{call}` one of (in order) `myself`, `create`, `search-1` to `search-4`, `read-description`, `comment`, `status-1`, `transitions-1`, `resolve`, `status-2`, `transitions-2`, `reopen`, `status-3`. Each file is a JSON object with exactly these keys: `seq` (n); `call`; `started_at` (UTC, RFC 3339 with milliseconds); `duration_ms`; `request` (`method`; `url`, with the connector instance's address of `docs/31-demo-data/07-settings.yaml` in place of the real base address; `headers`, the headers the spike set, with `Authorization` and `x-api-key` values `<redacted>`; `body`, the text as sent); `response` (`status`; `headers`, only `Content-Type`; `body`, the text as received) or `null`; `error` (`null`, or the text of a connection failure or timeout). No file holds a secret: the spike checks every file before it writes it (P-06 spec Section 6.2).

`url` starts with `${endpoint.jira}`. In the bodies the site's address is `${endpoint.jira}`, the account's email `<email>` and its account ID `<account-id>` (also where it was percent-encoded); in answer bodies that are JSON, every value of a key `accountId`, `emailAddress`, `displayName` or `avatarUrls` is `"<redacted>"`, and the body is written again as JSON (equal in content to the answer, not in text).
