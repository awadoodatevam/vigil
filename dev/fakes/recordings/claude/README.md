# Recorded Claude API calls

The calls of one run of the Claude spike (`spikes/providers/run.sh claude`, package P-06): the SL-T-1 and SL-T-2 structured-output requests of AR-G-20 with the storm incident built from `docs/31-demo-data/`, a request truncated at 16 output units, and a request with an invalid key. They are the payloads of the `claude` connector tests of P-19.

One file per call, `{n:04d}-{call}.json` (`n` from 1 in call order), `{call}` one of (in order) `sl-t-1`, `sl-t-2` (not made when the SL-T-1 answer was not accepted), `truncated`, `bad-key`. Each file is a JSON object with exactly these keys: `seq` (n); `call`; `started_at` (UTC, RFC 3339 with milliseconds); `duration_ms`; `request` (`method`; `url`, with the connector instance's address of `docs/31-demo-data/07-settings.yaml` in place of the real base address; `headers`, the headers the spike set, with `Authorization` and `x-api-key` values `<redacted>`; `body`, the text as sent); `response` (`status`; `headers`, only `Content-Type`; `body`, the text as received) or `null`; `error` (`null`, or the text of a connection failure or timeout). No file holds a secret: the spike checks every file before it writes it (P-06 spec Section 6.2). `url` is `${endpoint.claude}/v1/messages`.
