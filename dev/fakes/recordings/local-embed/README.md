# Recorded local embedding calls

The calls of one run of the similarity spike SB-T-03, runtime part (`spikes/providers/run.sh similarity`, package P-06), against `vigil-embed` on the main host: the 50 past incidents' search texts in one batched `/api/embed` call and the storm's search text alone (AR-G-24), each made twice. They are the payloads of the `local_embedding` connector tests of P-19.

One file per call, `{n:04d}-{call}.json` (`n` from 1 in call order), `{call}` one of (in order) `past-1`, `storm-1`, `past-2`, `storm-2`. Each file is a JSON object with exactly these keys: `seq` (n); `call`; `started_at` (UTC, RFC 3339 with milliseconds); `duration_ms`; `request` (`method`; `url`, with the connector instance's address of `docs/31-demo-data/07-settings.yaml` in place of the real base address; `headers`, the headers the spike set, with `Authorization` and `x-api-key` values `<redacted>`; `body`, the text as sent); `response` (`status`; `headers`, only `Content-Type`; `body`, the text as received) or `null`; `error` (`null`, or the text of a connection failure or timeout). No file holds a secret: the spike checks every file before it writes it (P-06 spec Section 6.2). `url` is `${endpoint.local_embedding}/api/embed`.
