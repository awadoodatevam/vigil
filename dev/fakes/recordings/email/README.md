# Recorded SMTP messages

The messages of one run of the email spike AR-SP-02 (`spikes/providers/run.sh email`, package P-07): 10 messages in the form of AR-K-20 to each of the shared mailboxes `noc-l1` and `dbops-engineer` (`mailbox.noc-l1` and `mailbox.dbops-engineer` of `deploy/values/demo.yaml`), sent over SMTP with STARTTLS to Amazon SES. They are the payloads of the `email` connector tests of P-22.

One file per message whose `MAIL` command was made, `{n:04d}-send-{key}-{k}.json` (`n` from 1 in send order, `{key}` `noc-l1` then `dbops-engineer`, `{k}` from 1 to 10). The connection steps (connect, `EHLO`, `STARTTLS`, login) are not recorded. Each file is a JSON object with exactly these keys: `seq` (n); `call` (`send-{key}-{k}`); `started_at` (UTC, RFC 3339 with milliseconds) and `duration_ms`, from just before `MAIL` to the last reply; `request` (`method` `SMTP`; `url` `${endpoint.smtp}`; `headers`, every header of the message in order, `From`, `To`, `Subject`, `Date`, `MIME-Version`, `Content-Type`, `Content-Transfer-Encoding`, with its value as the message holds it; `body`, the text after the first empty line of the message as sent, decoded as UTF-8: the four lines joined and ended by CRLF); `response` (`status`, the code of the last reply received; `headers` `{}`; `body`, that reply's text, decoded as UTF-8) or `null` when no reply was received; `error` (`null`, or the text of the exception that ended the transaction).

No file holds the SMTP username or password, the base64 of either, or the base64 of the `AUTH PLAIN` string: the spike checks every file before it writes it (P-06 spec Section 6.2, P-07 spec Section 6.2). The two mailbox addresses are deployment values, not secrets (AR-B-07, AR-K-21).
